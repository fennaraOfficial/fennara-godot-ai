Fennara 为编程智能体提供能够理解 Godot 的检查、编辑、验证、截图和运行时反馈。它补充而非取代普通仓库和 shell 工具。

本页说明每个工具的能力、调用成功意味着什么，以及重要限制和故障情况。实时工具 schema 始终是精确参数、结果字段、限制和智能体说明的规范源。已安装项目还会在 `addons/fennara/ai/` 中获得精简指南和按需知识。

<a id="tool-surfaces"></a>
## 工具界面

Codex、Claude Code、Cursor 和 Gemini 等外部 MCP 客户端通过本地 `fennara-mcp` 进程连接。它们使用自己的模型账户，并把常规文件、搜索、diff 和 shell 工具与 Fennara 配合使用。

内置 Fennara 聊天使用同一守护进程和 Godot 桥接。它可以调用相同 Godot 工具，并提供项目范围的 `read_file` 和 `exec_command`。提供商和模型设置属于内置聊天，而不属于 MCP 服务器。

`fennara_status` 向外部 MCP 客户端提供。内置聊天已经从守护进程获得连接和活动项目状态。

<a id="typical-workflow"></a>
## 典型工作流

1. 使用外部 MCP 客户端时确认已连接项目。
2. 检查相关场景、资源、类、导入状态或项目设置。
3. 进行最小有用编辑。
4. 运行诊断或场景验证。
5. 需要视觉或行为证据时使用截图或运行时工具。

编辑器文件系统扫描或导入时可能短暂忙碌。请在资源工具报告就绪后使用它们。

<a id="connection"></a>
## 连接

<a id="fennarastatus"></a>
### `fennara_status`

报告 MCP 服务器、守护进程、活动 Godot 项目、已连接编辑器会话、组件版本、渲染上下文、公开工具和编辑器文件系统就绪状态。

正常行为：

- 返回一个纯文本状态块。
- 区分已就绪的编辑器文件系统与正在扫描或导入的状态。
- 报告面向资源的工具当前是否就绪。
- 显示版本差异，便于诊断安装不匹配。

重要限制和故障：

- 它报告项目级就绪状态，不保证某个特定资源路径就绪。
- 守护进程断开、没有活动项目或 Godot 插件断开时，会直接报告，而不会假装项目就绪。
- Godot 重新导入文件时，就绪状态可能短暂变化。

<a id="inspection"></a>
## 检查

<a id="getscenetree"></a>
### `get_scene_tree`

通过 Godot 加载场景并返回节点层级、节点类、附加脚本和实例化子场景。返回路径可供其他场景工具使用。

正常行为：

- 读取已创作场景，不会重写。
- 编辑前显示节点和实例结构。
- 结果聚焦层级，不展开所有资源。

重要限制和故障：

- 它不是完整的 3D 资源、网格、材质、骨架或动画报告。
- Godot 无法加载的场景会返回失败，不会猜测场景树。
- 大型资源细节应使用定向属性或脚本检查。

<a id="getnodeproperties"></a>
### `get_node_properties`

显示所选节点中与类默认值不同的属性，并展开嵌入资源的有用摘要。

正常行为：

- 一次最多支持五个节点目标。
- 读取导出的 GDScript 属性和可用 C# 脚本元数据。
- 摘要动画、主题、瓦片数据、网格库、精灵帧和动画图等资源，而不是输出不透明值。

重要限制和故障：

- 它针对节点，不是完整场景资源清单。
- 导入源资源可能比已创作 `.tscn` 节点公开的信息更少。需要直接检查生成的导入资源时使用 `run_asset_import_script`。
- 无效节点路径会报告，不会静默忽略。

<a id="getclassinfo"></a>
### `get_class_info`

返回 Godot 类的真实 API，包括继承、属性、方法、信号、枚举、常量和可用文档。

正常行为：

- 运行时 ClassDB 信息来自已连接 Godot 编辑器。
- 内置类使用与已连接 Godot 主次版本匹配的官方 XML 文档，找不到时明确回退到 `master`。
- GDExtension 和原生插件类返回可用运行时类及属性信息，不会假装拥有官方 Godot 文档。

重要限制和故障：

- 匹配的上游类 XML 不可用或响应接收不完整时，文档可能不完整。
- 只在运行时表现的行为可能仍需小型编辑器端脚本探针。
- 不存在的类名会报告缺失。

<a id="editing"></a>
## 编辑

<a id="writeorupdatefile"></a>
### `write_or_update_file`

创建、重写项目文本文件，或在其中进行精确替换。

正常行为：

- `write` 用完整内容创建或替换文件。
- `update` 替换一个唯一的精确文本块。
- GDScript 和 shader 编辑自动返回 Godot 诊断。
- shader 编辑还会尝试通过 Godot 重新序列化引用它的场景和资源，避免嵌入材质数据过期。
- C# 写入可以组成多文件编辑，之后再请求一次项目诊断构建。

重要限制和故障：

- 更新文本不存在或有歧义时会失败，不会更改任意匹配。
- 受保护的 Fennara、Git、Godot 缓存、插件清单和项目设置路径不能通过此工具编辑。
- 不用于直接修改 `.tscn`、`.tres` 或 `.res`。
- 不会在每次 C# 写入后运行验证。相关 C# 编辑完成后应执行项目诊断扫描。
- 无法安全重新序列化的 shader 所有者会报告为跳过或警告。

<a id="runsceneeditscript"></a>
### `run_scene_edit_script`

针对一个已创作场景或 Godot 资源图运行一次编辑器时 GDScript 工作脚本。它是通过 Godot 对象模型和序列化器检查或编辑场景的结构化方式。

正常行为：

- 检查模式加载分离的只读场景图，绝不保存。
- 编辑模式可添加、移除、重命名或重新挂接节点，分配资源、更改属性、创建场景并通过 Godot 序列化保存。
- 只有工作脚本把上下文标记为已修改时才保存现有场景。
- 新节点和 PackedScene 实例使用明确所有权辅助函数，确保 Godot 序列化预期结构。
- 执行前运行脚本诊断，保存场景后继续验证。
- Godot 能安全序列化请求覆盖时，会保留继承场景根。
- 每次调用返回有效临时工作脚本路径，失败脚本可直接修正，无需从头创建。

重要限制和故障：

- 加载图不等同于按下 Run Scene。SceneTree 相关游戏 API、计时器、帧处理和全局变换在分离节点上可能行为不同或失败。
- 检查模式阻止 Fennara 上下文修改辅助函数，但任意 GDScript 仍必须避免直接文件系统、编辑器、OS 和资源保存副作用。
- `.glb` 和 `.gltf` 等导入源文件不会由此工具保存，导入设置属于 `run_asset_import_script`。
- 错误的 PackedScene 内部所有权会被拒绝，因为它可能扁平化或复制实例内容。
- 如果保存会扁平化继承根，Fennara 会恢复原文件并报告失败。
- 诊断或运行时错误会停止编辑。失败结果不会创建或更新目标场景，但临时工作脚本可能保留供重试。

<a id="runassetimportscript"></a>
### `run_asset_import_script`

针对导入源资源及其 Godot 导入配置运行一次有界编辑器时 GDScript 工作脚本。支持已有匹配 `.import` 旁车文件的模型、纹理、音频、字体和其他格式。

检查模式正常行为：

- 报告导入器、生成资源类、导入有效性、带类型的当前选项、生成文件和上游依赖。
- 加载生成资源，不复用过期嵌套缓存条目。
- 可在实时编辑器 SceneTree 中临时实例化导入 PackedScene 进行有界检查，然后移除且不保存。
- 对生成子资源提供有界摘要。
- 检查模式绝不持久化导入选项更改。

编辑模式正常行为：

- 暂存支持的现有导入选项，同时保留其原生 Godot Variant 类型。
- 让实时编辑器通过 `EditorFileSystem` 执行重新导入。
- 只有规范导入设置、生成输出、编辑器文件系统状态和全新深层资源加载均验证成功后才报告成功。
- 验证失败时尝试恢复并重新导入上一个配置，并报告恢复是否成功。

重要限制和故障：

- 源文件必须已导入且有有效 `.import` 旁车文件。
- 第一版编辑仅支持受支持内置纹理和场景导入器中，被归类为安全生成缓存更改的选项。
- 导入器身份、导入脚本、`_subresources`、外部提取路径和影响未知的选项只能检查。
- 未知或不支持的选项以及 Variant 类型错误的值会失败，不会强制转换。
- 直接修改 `.import` 会被检测、恢复并报告失败，旁车持久化由 Fennara 负责。
- 配置根脚本的导入场景不会由检查辅助函数临时实例化。
- 依赖项表示导入所选资源需要的文件，不表示使用模型、纹理、音频或字体的下游项目使用者。
- 脚本诊断、运行时错误、重新导入错误、缺少生成文件、无效文件系统状态或重新加载失败都会阻止成功。
- 大数组和资源内部会被限制或摘要。有界结果不表示每个顶点、关键帧或依赖都已内联输出。

<a id="projectsettings"></a>
### `project_settings`

读取和更改结构化 Godot 项目设置、autoload、应用元数据、渲染和显示设置及输入动作。

正常行为：

- 使用 Godot 感知结构化操作，而不是直接替换 `project.godot` 文本。
- 列出输入动作的 deadzone、事件数量和易读事件摘要。
- 添加或更新控制时支持结构化输入事件。

重要限制和故障：

- 未知操作或无效设置值会被报告。
- 此工具不能取代场景或脚本编辑。
- 影响启动、渲染、输入或插件行为的更改仍应验证。

<a id="checks"></a>
## 检查

<a id="scriptdiagnostics"></a>
### `script_diagnostics`

为脚本和 shader 运行 Godot 感知诊断。

正常行为：

- 定向 GDScript 和 shader 调用最多支持五个文件。
- GDScript 诊断来自 Godot 语言服务器。
- shader 诊断来自 Godot shader 解析器。
- 定向 GDScript 检查还会在内存中加载相关场景，把脚本附加引发的错误关联到脚本和场景。
- 项目扫描检查 GDScript 和 shader，有 C# 项目时再执行一次隔离增量 C# 构建。
- 诊断 C# 程序集与编辑器普通运行时程序集分离。

重要限制和故障：

- 不支持定向 C# 文件诊断，C# 使用项目扫描。
- 全项目扫描跳过逐场景实例化，可能漏掉只有通过特定场景加载脚本时出现的问题。
- 语言服务器、解析器或构建失败会作为诊断失败返回，不会视为干净结果。
- 诊断只证明代码能在测试上下文中解析或编译，不证明游戏逻辑正确。

<a id="validatescene"></a>
### `validate_scene`

检查一个或多个场景的结构问题，并在支持时运行短暂无头启动。

正常行为：

- 最多接受十个场景路径。
- 结构检查涵盖脚本或资源缺失、无效节点路径、同级重名、循环场景依赖和相关导出引用。
- 可选或运行时赋值的导出引用报告为说明，而不是无条件失败。
- 结构干净的已创作场景会运行三秒无头启动，并保留日志和资源。
- 重复发现会分组，避免大场景淹没结果。

重要限制和故障：

- 导入源场景不能直接作为已创作项目场景启动，因此只做结构验证。
- Fennara 会有意在验证窗口结束后停止进程，该停止代码本身不算失败。
- 短暂启动无法验证所有游戏路径、视觉、性能、动画质量或用户交互。
- 结构错误会阻止该场景的运行时检查。

<a id="visual-and-runtime-feedback"></a>
## 视觉与运行时反馈

<a id="screenshotscene"></a>
### `screenshot_scene`

从已创作场景和受支持的导入 3D 资源捕获视觉证据。

正常行为：

- 每个场景在隔离 SubViewport 中实例化，不打开或修改源场景。
- 自动 3D 取景在资源没有环境或灯光时可添加中性预览照明。
- `scene_path` 是唯一必需输入。省略 `code` 和 `script_path` 时，以自动取景捕获分离根。
- GDScript 可用普通 Godot 代码选择一个或一组节点、自由分组主体、显隐场景部分、临时修改分离场景，并通过 `ctx.capture(...)` 请求捕获。这些修改会渲染但不会保存。
- `await ctx.capture(...)` 在该精确时点渲染场景并返回普通 Godot `Image`。工作脚本可检查、比较、缩放、丢弃或组合图片，再用 `ctx.output(image, description)` 发布所选结果。
- 对最多八个主体，如果脚本化 3D 捕获未指定 `view` 或 `camera`，Fennara 会检查 17 个确定视角，选择兼顾可见性、可读尺寸、边缘间距和低重叠的视角。已知方向时使用明确视角或相机，远距离主体在同一帧会过小时使用多次捕获。
- 截图脚本只获得 `ctx.root`、`await ctx.capture(...)`、`ctx.sheet(...)`、`ctx.output(...)`、`ctx.log(...)` 和 `ctx.error(...)`。`ctx.sheet(...)` 按调用方顺序将图片组合为确定、可选带标签的页面，不自行选择状态或发布。需要精确取景时，可在捕获选项中传入 `ctx.root` 下临时 Camera2D 或 Camera3D。
- 不接受相机路径、目标路径、视图矩形和顶层取景参数，所有选择和取景都在工作脚本中完成。
- 每个发布图片都被保存并列出。支持图片的 MCP 客户端和内置聊天模型会按调用顺序获得前六个输出作为独立图片上下文。后续输出仍可从保存路径访问，收据会明确说明省略图片数量。
- 稀疏捕获会连同取景指标和部分状态返回，不会隐藏图片。

重要限制和故障：

- 对大型室内、房间、关卡或特殊蒙皮资源，自动取景不一定能推断艺术上合适的视角。
- 返回图片可能有效，但内容验证仍会报告取景稀疏或不确定。
- 纯文本模型只能收到收据和路径，无法直接看到图片像素。
- 加载、渲染、捕获所有权或文件保存失败都会报告。
- 未知的旧版截图参数会被迁移错误拒绝。
- 脚本解析错误、运行时错误、缺少捕获调用、分离根外节点和无效临时相机会在不捕获的情况下报告。

<a id="runtimesession"></a>
### `runtime_session`

启动、检查或停止由守护进程管理的窗口化 Godot 场景。

正常行为：

- 启动前运行门禁检查。
- 成功启动返回会话标识、进程状态、日志路径、启动发现和可用捕获信息。
- 状态调用返回新的运行时输出，不丢弃完整会话日志。
- 停止调用返回最终进程和日志信息。
- C# 项目启动前会真实构建到 Godot 普通 Debug 输出，使进程使用当前程序集。
- 运行时日志是 Godot 输出、运行时错误、辅助标记、捕获和停止事件的规范源。

重要限制和故障：

- 全局一次只能有一个由守护进程管理的运行时会话。
- 启动门禁失败会阻止场景打开。
- C# 运行时构建可能触发已打开编辑器的普通程序集重载。
- 启动就绪标记可能在初始响应后到达，并出现在后续状态调用中。
- 受管理会话是独立 Godot 进程，不是编辑器内手动运行的场景。

<a id="runtimescript"></a>
### `runtime_script`

在活动受管理运行时会话中执行有界 GDScript 探针或输入驱动脚本。

正常行为：

- 可检查实时节点、记录发现、等待状态、发送映射或底层输入、执行射线查询、与基础 UI 交互并捕获帧。
- 可用 `ctx.frame()` 收集未保存视口图片，用 `ctx.sheet()` 组合与截图脚本相同的调用方控制图片页，并通过 `ctx.output()` 直接发布派生图片而不在游戏中显示。
- 脚本可以结束而受管理场景保持打开，以便继续运行探针。
- 可用时，结果包含诊断、运行时发现、捕获路径、日志路径和会话状态。

重要限制和故障：

- 需要有效且活动的 `runtime_session` 标识。
- 运行时脚本不是编辑器 `@tool` 脚本，不能作为场景编辑工作脚本。
- 无效诊断、超时、运行时错误、已关闭会话或节点不可用都会报告。
- 探针必须有界，不能取代永久游戏自动化框架。

<a id="scrapeeditor"></a>
### `scrape_editor`

用户通过 Godot 编辑器手动运行场景后，读取精简调试器快照。

正常行为：

- 对重复调试器问题分组，并限制噪声细节。
- 帮助检查不属于受管理运行时会话的编辑器运行输出。

重要限制和故障：

- 它有意比读取所有编辑器 UI 元素或日志行更窄。
- 不应对 `runtime_session` 启动的场景使用，受管理运行时日志更完整。
- 未手动运行任何内容时，可能没有可用调试器状态。

<a id="built-in-chat-tools-and-controls"></a>
## 内置聊天工具与控件

<a id="readfile"></a>
### `read_file`

通过 Godot 路径处理读取项目范围文本文件和支持的图片。需要 `res://` 规范化或图片处理时很有用。广泛源代码导航仍属于普通仓库工具。

<a id="execcommand"></a>
### `exec_command`

以活动项目根目录为默认工作目录运行一个非交互命令。

正常行为：

- 在时间和输出限制内捕获标准输出与错误。
- 拒绝活动项目根目录之外的工作目录。
- 存储守护进程端原始收据，避免大段输出长期留在模型对话中。

重要限制和故障：

- 它提供项目根限制和审批处理，不是操作系统沙箱。
- 不提供交互终端、PTY、后台会话、标准输入流或任意环境配置。
- 非零退出、超时和输出截断都会报告。

<a id="chat-controls"></a>
### 聊天控件

内置聊天为项目修改和运行时工具调用提供审批模式。只读检查可以立即运行，修改或执行可要求明确审批。Full access 会移除这些提示，但不会绕过硬安全检查。

可通过 **Add to Chat** 附加 Godot 脚本编辑器中选中的代码，编辑框在发送前显示附件。`/provider` 打开提供商设置，`/model` 打开模型选择。它们是聊天命令，不是 MCP 工具。

<a id="what-fennara-does-not-replace"></a>
## Fennara 不取代什么

以下工作请使用普通开发工具：

- 广泛的仓库搜索和导航
- 普通文本文件读取
- diff 和版本控制
- 不需要 Godot 反馈的编辑
- 一般 shell 工作

当答案取决于 Godot 的理解、导入、序列化、渲染、验证或项目运行时，请使用 Fennara。
