# 도구

Fennara는 코딩 에이전트에 Godot 인식 검사, 편집, 검증, 스크린샷, 런타임 피드백을 제공합니다. 일반 저장소 및 셸 도구를 대체하지 않고 보완합니다.

이 페이지는 각 도구가 할 수 있는 일, 호출 성공의 의미, 중요한 제한 및 실패 사례를 설명합니다. 정확한 인수, 결과 필드, 제한, 에이전트 지침의 정본은 실시간 도구 스키마입니다. 설치된 프로젝트는 `addons/fennara/ai/`에도 작은 지침과 필요할 때 불러오는 지식을 받습니다.

<a id="tool-surfaces"></a>
## 도구 화면

Codex, Claude Code, Cursor, Gemini를 포함한 외부 MCP 클라이언트는 로컬 `fennara-mcp` 프로세스를 통해 연결됩니다. 자체 모델 계정과 일반 파일, 검색, diff, 셸 도구를 Fennara와 함께 사용합니다.

Fennara 내장 채팅은 같은 데몬과 Godot 브리지를 사용합니다. 같은 Godot 도구를 호출하며 프로젝트 범위의 `read_file` 및 `exec_command` 도구도 제공합니다. 제공업체 및 모델 설정은 MCP 서버가 아니라 내장 채팅에 속합니다.

`fennara_status`는 외부 MCP 클라이언트에서 사용할 수 있습니다. 내장 채팅은 이미 데몬에서 연결 및 활성 프로젝트 상태를 받습니다.

각 외부 MCP 프로세스는 시작할 때 라우팅 모드 하나를 선택합니다. `bound` 프로세스는 정규
Project Root를 기준으로 라우팅합니다. `legacy_unbound` 프로세스는 독에서 선택한 호환
대상을 사용하므로 격리된 동시 작업에 적합하지 않습니다.

<a id="typical-workflow"></a>
## 일반적인 워크플로

1. 외부 MCP 클라이언트를 사용할 때 연결된 프로젝트를 확인합니다.
2. 관련 씬, 리소스, 클래스, 가져오기 상태 또는 프로젝트 설정을 살펴봅니다.
3. 가장 작은 유용한 편집을 수행합니다.
4. 진단 또는 씬 검증을 실행합니다.
5. 시각적 또는 동작 증거가 중요하면 스크린샷이나 런타임 도구를 사용합니다.

에디터 파일 시스템은 검사 또는 가져오기 중 일시적으로 바쁠 수 있습니다. 자산 도구는 준비 상태가 보고된 뒤 사용해야 합니다.

<a id="connection"></a>
## 연결

<a id="fennarastatus"></a>
### `fennara_status`

MCP 서버, 데몬, 라우팅 모드, 선택된 Godot 에디터, 연결된 에디터 세션, 구성 요소 버전,
렌더링 맥락, 광고된 도구, 에디터 파일 시스템 준비 상태를 보고합니다.

정상 동작:

- 일반 텍스트 상태 블록 하나를 반환합니다.
- 바인딩된 프로세스의 경우 바인딩 소스(`cli`, `environment`, `cwd`), 정규 Project Root,
  에디터 상태(`connected`, `not_connected`, `ambiguous`)를 보고합니다.
- 독에서 선택한 레거시 MCP Target을 Project Binding과 따로 보고합니다.
- 준비된 에디터 파일 시스템과 검사 또는 가져오기 중인 상태를 구분합니다.
- 자산 대상 도구가 현재 준비되었는지 보고합니다.
- 일치하지 않는 설치를 진단할 수 있도록 버전 차이를 표시합니다.

중요한 제한 및 실패:

- 특정 자산 경로가 아니라 프로젝트 수준 준비 상태를 보고합니다.
- 일치하는 에디터가 없는 바인딩된 루트는 재시도 가능한 `bound_project_not_connected`를 보고하며
  독 대상으로 절대 대체하지 않습니다.
- 바인딩된 루트에 중복 에디터가 있으면 `ambiguous_project_binding`을 보고하고 어떤 에디터도
  선택하지 않습니다.
- 데몬 연결 끊김, 호환 대상 없음, Godot 플러그인 연결 끊김을 준비된 프로젝트로 처리하지 않고
  직접 보고합니다.
- 바인딩 일치 실패 시 관련 없는 에디터의 파일 시스템 준비 상태나 겉보기성 성공을 표시하지 않습니다.
- 레거시 미바인딩 모드는 동시 작업 경고를 보고합니다.
- Godot이 파일을 다시 가져오는 동안 준비 상태가 잠시 바뀔 수 있습니다.

<a id="inspection"></a>
## 검사

<a id="getscenetree"></a>
### `get_scene_tree`

Godot을 통해 씬을 불러오고 노드 계층, 노드 클래스, 연결된 스크립트, 인스턴스화된 하위 씬을 반환합니다. 반환 경로는 다른 씬 도구에서 사용할 수 있습니다.

정상 동작:

- 작성된 씬을 다시 쓰지 않고 읽습니다.
- 편집 전에 노드와 인스턴스 구조를 볼 수 있게 합니다.
- 모든 리소스를 펼치지 않고 계층에 집중합니다.

중요한 제한 및 실패:

- 완전한 3D 자산, 메시, 머티리얼, 스켈레톤 또는 애니메이션 보고서가 아닙니다.
- Godot이 불러올 수 없는 씬은 추측한 트리가 아니라 실패를 반환합니다.
- 큰 리소스 세부 정보는 대상 속성 또는 스크립트 검사에 속합니다.

<a id="getnodeproperties"></a>
### `get_node_properties`

선택한 노드에서 클래스 기본값과 다른 속성을 표시하고 임베디드 리소스의 유용한 요약을 펼칩니다.

정상 동작:

- 한 번에 최대 다섯 노드 대상을 지원합니다.
- 내보낸 GDScript 속성과 사용 가능한 C# 스크립트 메타데이터를 읽습니다.
- 애니메이션, 테마, 타일 데이터, 메시 라이브러리, 스프라이트 프레임, 애니메이션 그래프 같은 리소스를 불투명한 값 대신 요약합니다.

중요한 제한 및 실패:

- 노드 대상 도구이며 전체 씬 리소스 목록이 아닙니다.
- 가져온 원본 자산은 작성된 `.tscn` 노드보다 적은 정보를 노출할 수 있습니다. 생성된 가져오기 리소스를 직접 살펴봐야 하면 `run_asset_import_script`를 사용하세요.
- 잘못된 노드 경로는 조용히 무시하지 않고 보고합니다.

<a id="getclassinfo"></a>
### `get_class_info`

상속, 속성, 메서드, 시그널, enum, 상수, 사용 가능한 문서를 포함한 Godot 클래스의 실제 API 표면을 반환합니다.

정상 동작:

- 런타임 ClassDB 정보는 연결된 Godot 에디터에서 옵니다.
- 내장 클래스는 연결된 주 버전 및 부 버전과 일치하는 공식 Godot XML 문서를 사용하고 명시적인 `master` 대체 경로를 둡니다.
- GDExtension 및 네이티브 애드온 클래스는 공식 Godot 문서가 있는 척하지 않고 사용 가능한 런타임 클래스와 속성 정보를 반환합니다.

중요한 제한 및 실패:

- 일치하는 업스트림 클래스 XML이 없거나 응답을 완전히 받지 못하면 문서 조회가 불완전할 수 있습니다.
- 런타임 전용 동작에는 작은 에디터 측 스크립트 탐색이 필요할 수 있습니다.
- 존재하지 않는 클래스 이름은 누락으로 보고합니다.

<a id="editing"></a>
## 편집

<a id="writeorupdatefile"></a>
### `write_or_update_file`

프로젝트 텍스트 파일을 만들거나 다시 쓰거나 정확히 치환합니다.

정상 동작:

- `write`는 전체 내용으로 파일을 만들거나 교체합니다.
- `update`는 고유하게 일치하는 정확한 텍스트 블록 하나를 교체합니다.
- GDScript 및 셰이더 편집은 Godot 진단을 자동으로 반환합니다.
- 셰이더 편집은 임베디드 머티리얼 데이터가 오래되지 않도록 참조 씬과 리소스를 Godot을 통해 다시 직렬화하려고 합니다.
- 관련 C# 편집이 끝난 뒤 프로젝트 진단 빌드 하나를 요청할 수 있도록 C# 쓰기는 여러 파일 편집을 구성할 수 있습니다.

중요한 제한 및 실패:

- 모호하거나 없는 업데이트 텍스트는 임의 일치를 바꾸지 않고 실패합니다.
- 보호된 Fennara, Git, Godot 캐시, 플러그인 매니페스트, 프로젝트 설정 경로는 이 도구로 편집할 수 없습니다.
- 원시 `.tscn`, `.tres`, `.res` 수술용이 아닙니다.
- C# 검증은 개별 쓰기마다 실행되지 않습니다. 관련 C# 편집을 끝낸 뒤 프로젝트 진단 검사를 사용하세요.
- 안전하게 다시 직렬화할 수 없는 셰이더 소유자는 건너뜀 또는 경고로 보고합니다.

<a id="runsceneeditscript"></a>
### `run_scene_edit_script`

작성된 씬 또는 Godot 리소스 그래프 하나를 대상으로 에디터 시간 GDScript 작업자 하나를 실행합니다. Godot 객체 모델과 직렬화기를 통해 씬을 검사하거나 편집하는 구조화된 방법입니다.

검사 모드의 정상 동작:

- 분리된 읽기 전용 씬 그래프를 불러오고 절대 저장하지 않습니다.
- 편집 모드는 노드 추가, 제거, 이름 변경, 부모 변경, 리소스 할당, 속성 변경, 씬 생성, Godot 직렬화를 통한 저장을 할 수 있습니다.
- 기존 씬은 작업자가 컨텍스트를 수정됨으로 표시한 경우에만 저장됩니다.
- 새 노드와 PackedScene 인스턴스는 명시적인 소유권 헬퍼를 사용하여 Godot이 의도한 구조를 직렬화하게 합니다.
- 실행 전 스크립트 진단을 수행하고 저장된 씬은 후속 검증을 받습니다.
- Godot이 요청한 재정의를 안전하게 직렬화할 수 있으면 상속 씬 루트를 보존합니다.
- 모든 호출은 실제 임시 작업자 경로를 반환하므로 실패한 작업자를 처음부터 다시 만들지 않고 고칠 수 있습니다.

중요한 제한 및 실패:

- 불러온 그래프는 Run Scene을 누른 것과 같지 않습니다. SceneTree에 의존하는 게임플레이 API, 타이머, 프레임 처리, 전역 변환은 분리된 노드에서 다르게 동작하거나 실패할 수 있습니다.
- 검사 모드는 Fennara 컨텍스트 변경 헬퍼를 차단하지만 임의 GDScript도 직접 파일 시스템, 에디터, OS, 리소스 저장 부작용을 피해야 합니다.
- `.glb`, `.gltf` 같은 가져온 원본 파일은 이 도구로 저장하지 않습니다. 가져오기 설정은 `run_asset_import_script`에 속합니다.
- 잘못된 PackedScene 내부 소유권은 인스턴스 내용을 평면화하거나 중복할 수 있으므로 거부됩니다.
- 저장이 상속 루트를 평면화하면 Fennara가 원본 파일을 복원하고 실패를 보고합니다.
- 진단 또는 런타임 오류는 편집을 중지합니다. 실패 결과는 대상 씬을 만들거나 업데이트하지 않지만 재시도용 임시 작업자 스크립트는 남을 수 있습니다.

<a id="runassetimportscript"></a>
### `run_asset_import_script`

가져온 원본 자산과 Godot 가져오기 구성을 대상으로 제한된 에디터 시간 GDScript 작업자 하나를 실행합니다. 일치하는 `.import` 사이드카가 이미 있는 모델, 텍스처, 오디오, 글꼴 및 기타 형식을 지원합니다.

검사 모드의 정상 동작:

- 가져오기 도구, 생성된 리소스 클래스, 가져오기 유효성, 형식이 있는 현재 옵션, 생성 파일, 업스트림 의존성을 보고합니다.
- 오래된 중첩 캐시 항목을 재사용하지 않고 생성된 리소스를 불러옵니다.
- 가져온 PackedScene을 실행 중인 에디터 SceneTree에 임시로 인스턴스화해 제한된 검사를 한 뒤 저장하지 않고 제거할 수 있습니다.
- 생성된 하위 리소스의 제한된 요약을 제공합니다.
- 검사 모드에서는 가져오기 옵션 변경을 절대 저장하지 않습니다.

편집 모드의 정상 동작:

- 지원되는 기존 가져오기 옵션을 네이티브 Godot Variant 형식을 보존하면서 스테이징합니다.
- 실행 중인 에디터가 `EditorFileSystem`을 통해 다시 가져오기를 수행하게 합니다.
- 정식 가져오기 설정, 생성 출력, 에디터 파일 시스템 상태, 새로운 깊은 리소스 불러오기가 검증된 뒤에만 성공을 보고합니다.
- 검증 실패 시 이전 구성을 복원하고 다시 가져오려고 시도하며 복구 성공 여부를 보고합니다.

중요한 제한 및 실패:

- 원본 파일은 이미 가져와졌고 유효한 `.import` 사이드카가 있어야 합니다.
- 버전 1 편집은 지원되는 내장 텍스처 및 씬 가져오기 도구에서 안전한 생성 캐시 변경으로 분류된 옵션만 허용합니다.
- 가져오기 도구 식별자, 가져오기 스크립트, `_subresources`, 외부 추출 경로, 효과를 알 수 없는 옵션은 검사 전용입니다.
- 알 수 없는 옵션, 지원되지 않는 옵션, 잘못된 Variant 형식 값은 강제 변환하지 않고 실패합니다.
- 직접 `.import` 파일을 수정하면 이를 감지하고 복원한 뒤 실패를 보고합니다. 사이드카 저장은 Fennara가 담당합니다.
- 루트 스크립트가 설정된 가져온 씬은 검사 헬퍼가 임시 인스턴스화하지 않습니다.
- 의존성은 선택한 자산을 가져오는 데 필요한 파일을 설명합니다. 모델을 쓰는 씬, 텍스처를 쓰는 머티리얼, 오디오를 재생하는 스크립트, 글꼴을 쓰는 테마 같은 다운스트림 프로젝트 소비자는 식별하지 않습니다.
- 스크립트 진단, 런타임 오류, 다시 가져오기 오류, 생성 파일 누락, 잘못된 파일 시스템 상태, 다시 불러오기 실패가 있으면 성공하지 않습니다.
- 도구 출력을 보호하기 위해 큰 배열과 리소스 내부는 제한하거나 요약합니다. 제한된 결과가 모든 꼭짓점, 키 또는 의존성을 인라인으로 출력했다는 뜻은 아닙니다.

<a id="projectsettings"></a>
### `project_settings`

구조화된 Godot 프로젝트 설정, autoload, 애플리케이션 메타데이터, 렌더링 및 표시 설정, 입력 액션을 읽고 변경합니다.

정상 동작:

- 원시 `project.godot` 텍스트 치환 대신 Godot 인식 구조화 작업을 사용합니다.
- 입력 액션을 deadzone, 이벤트 개수, 읽기 쉬운 이벤트 요약과 함께 나열합니다.
- 컨트롤을 추가하거나 업데이트할 때 구조화된 입력 이벤트를 지원합니다.

중요한 제한 및 실패:

- 알 수 없는 작업 또는 잘못된 설정 값을 보고합니다.
- 씬 또는 스크립트 편집을 대체하지 않습니다.
- 시작, 렌더링, 입력, 애드온 동작에 영향을 주는 변경은 계속 검증해야 합니다.

<a id="checks"></a>
## 검사

<a id="scriptdiagnostics"></a>
### `script_diagnostics`

스크립트와 셰이더에 Godot 인식 진단을 실행합니다.

정상 동작:

- 대상 GDScript 및 셰이더 호출은 최대 다섯 파일을 지원합니다.
- GDScript 진단은 Godot 언어 서버에서 옵니다.
- 셰이더 진단은 Godot 셰이더 파서에서 옵니다.
- 대상 GDScript 검사는 관련 씬도 메모리에 불러와 씬 연결 때문에 생긴 오류를 스크립트와 씬에 연관시킬 수 있습니다.
- 프로젝트 검사는 GDScript와 셰이더를 확인한 뒤 C# 프로젝트가 있으면 격리된 증분 C# 빌드 하나를 수행합니다.
- 진단 C# 어셈블리는 에디터의 일반 런타임 어셈블리와 분리됩니다.

중요한 제한 및 실패:

- 대상 C# 파일 진단은 지원하지 않습니다. C#은 프로젝트 검사를 사용합니다.
- 프로젝트 전체 검사는 씬별 인스턴스화를 건너뛰므로 특정 씬을 통해 스크립트를 불러올 때만 생기는 문제를 놓칠 수 있습니다.
- 언어 서버, 파서, 빌드 실패는 깨끗한 결과로 처리하지 않고 진단 실패로 반환합니다.
- 진단은 검사한 맥락에서 코드가 파싱 또는 컴파일될 수 있음을 증명할 뿐 게임플레이 정확성을 증명하지 않습니다.

<a id="validatescene"></a>
### `validate_scene`

하나 이상의 씬에서 구조 문제를 검사하고 지원되는 경우 짧은 헤드리스 시작 검사를 실행합니다.

정상 동작:

- 최대 열 개의 씬 경로를 받습니다.
- 구조 검사는 누락된 스크립트와 리소스, 잘못된 노드 경로, 중복 형제 이름, 순환 씬 의존성, 관련 내보낸 참조를 포함합니다.
- 선택 사항 또는 런타임 할당 내보낸 참조는 무조건 실패가 아니라 참고로 보고합니다.
- 구조 결과가 깨끗한 작성 씬은 로그와 아티팩트를 보존하는 3초 헤드리스 시작 검사를 받습니다.
- 이러한 범위 제한 검증 워커는 대화형 Runtime Slot을 차지하지 않습니다. 다른 프로젝트가
  Runtime Session을 소유하는 동안에도 검증을 진행할 수 있습니다.
- 반복 발견을 묶어 큰 씬이 결과를 넘치게 하지 않습니다.

중요한 제한 및 실패:

- 가져온 원본 씬은 작성된 프로젝트 씬처럼 직접 시작할 수 없으므로 구조 검증만 받습니다.
- Fennara는 검증 시간이 지나면 의도적으로 프로세스를 중지합니다. 해당 중지 코드만으로 씬 실패로 처리하지 않습니다.
- 짧은 시작 검사는 모든 게임플레이 경로, 시각 요소, 성능, 애니메이션 품질 또는 사용자 상호작용을 검증할 수 없습니다.
- 구조 오류가 있으면 해당 씬의 런타임 검사를 실행하지 않습니다.

<a id="visual-and-runtime-feedback"></a>
## 시각적 및 런타임 피드백

<a id="screenshotscene"></a>
### `screenshot_scene`

작성된 씬과 지원되는 가져온 3D 자산에서 시각적 증거를 캡처합니다.

정상 동작:

- 모든 씬을 격리된 SubViewport에 인스턴스화합니다. 스크린샷 캡처는 작성된 씬을 열거나 변경하지 않습니다.
- 자동 3D 프레이밍은 자산에 환경이나 조명이 없으면 중립적인 미리보기 조명을 추가할 수 있습니다.
- `scene_path`만 필수 입력입니다. `code`와 `script_path`가 모두 없으면 Fennara가 자동 프레이밍으로 분리된 루트를 캡처합니다.
- GDScript는 일반 Godot 코드로 노드 하나 또는 노드 배열을 선택하고, 대상을 자유롭게 묶고, 씬 부분을 표시하거나 숨기고, 분리된 씬을 임시 변경하며 `ctx.capture(...)`로 캡처를 요청할 수 있습니다. 임시 변경은 렌더링되지만 작성된 씬에 저장되지 않습니다.
- `await ctx.capture(...)`는 정확히 해당 시점의 씬 상태를 렌더링하고 일반 Godot `Image`를 반환합니다. 작업자는 선택한 결과를 `ctx.output(image, description)`으로 게시하기 전에 캡처 이미지를 검사, 비교, 크기 변경, 폐기 또는 결합할 수 있습니다.
- 최대 여덟 개의 선택 대상에서 스크립트 3D 캡처가 `view`와 `camera`를 생략하면 Fennara가 결정론적인 17개 시점을 검사하여 선택 노드의 가시성, 읽기 쉬운 크기, 가장자리 여백, 낮은 겹침을 선호하는 시점을 고릅니다. 유용한 방향을 이미 알면 명시적 view 또는 camera를 사용하고, 먼 대상이 한 프레임에서 너무 작아진다면 여러 캡처를 사용하세요.
- 스크린샷 작업자는 `ctx.root`, `await ctx.capture(...)`, `ctx.sheet(...)`, `ctx.output(...)`, `ctx.log(...)`, `ctx.error(...)`만 받습니다. `ctx.sheet(...)`는 상태를 선택하거나 게시하지 않고 호출자 순서의 Image를 결정론적이며 선택적으로 레이블이 있는 페이지로 합성합니다. 정확한 작성 프레이밍이 필요하면 캡처 옵션에서 `ctx.root` 아래의 임시 Camera2D 또는 Camera3D를 전달할 수 있습니다.
- 카메라 경로, 대상 경로, 뷰 사각형, 최상위 프레이밍 인수는 받지 않습니다. 모든 선택과 프레이밍은 작업자 스크립트에 있습니다.
- 게시된 모든 이미지는 저장되고 나열됩니다. 이미지 지원 MCP 클라이언트와 내장 채팅 모델은 호출 순서대로 처음 여섯 출력을 별도 이미지 맥락으로 받습니다. 이후 출력은 저장 경로로 사용할 수 있으며 영수증에 생략된 이미지 수가 명시됩니다.
- 희소 캡처는 이미지를 숨기지 않고 프레이밍 측정값 및 부분 상태와 함께 반환합니다.

중요한 제한 및 실패:

- 자동 프레이밍이 큰 실내, 방, 레벨 또는 특이한 스킨 자산의 예술적으로 유용한 시점을 항상 추론할 수는 없습니다.
- 내용 검증에서 프레이밍이 희소하거나 불확실하다고 보고해도 반환 이미지 자체는 유효할 수 있습니다.
- 텍스트 전용 모델은 영수증과 저장 경로를 받지만 첨부 이미지 픽셀을 직접 볼 수 없습니다.
- 불러오기, 렌더링, 캡처 소유권 또는 파일 저장 실패를 보고합니다.
- 알 수 없는 레거시 스크린샷 인수는 마이그레이션 오류로 거부합니다.
- 스크립트 파싱 오류, 런타임 오류, 캡처 호출 없음, 분리된 루트 밖의 노드, 잘못된 임시 카메라는 캡처하지 않고 보고합니다.

<a id="runtimesession"></a>
### `runtime_session`

데몬이 관리하는 창 있는 Godot 씬을 시작하거나 검사하거나 중지합니다.

정상 동작:

- 씬 프로세스를 시작하기 전에 시작 게이트를 실행합니다.
- 성공한 시작은 세션 식별자, 프로세스 상태, 로그 경로, 시작 발견, 사용 가능한 캡처 정보를 반환합니다.
- 시스템 전역 Runtime Slot이 사용 중이면 `availability: "busy"`, `slot_acquired: false`와 권장
  `retry_after_ms`를 포함한 성공적인 `busy` 도메인 결과를 반환합니다. 이 결과는 소유 프로젝트나
  세션을 노출하지 않습니다.
- 상태 호출은 전체 세션 로그를 버리지 않고 새로운 런타임 출력을 반환합니다.
- 중지는 최종 프로세스 및 로그 정보를 반환합니다.
- C# 프로젝트는 시작 전에 Godot의 일반 Debug 출력으로 실제 런타임 빌드를 수행하여 프로세스가 현재 어셈블리를 사용하게 합니다.
- 런타임 로그가 Godot 출력, 런타임 오류, 헬퍼 마커, 캡처, 중지 이벤트의 정본입니다.
- `start`는 선택적 `user_args`를 받습니다. Fennara는 각 문자열을 Godot의 `--` 구분자 뒤에 변경 없이 전달하므로 실행 중인 프로젝트에서 `OS.get_cmdline_user_args()`로 읽을 수 있습니다.

중요한 제한 및 실패:

- 전역에서 데몬이 관리하는 Runtime Session 하나만 시작 중이거나 실행 중일 수 있습니다. `busy`
  결과를 지터를 적용해 폴링하고, 새 시작을 마지막 원자적 확보로 취급하세요. 직전에 확인한 빈
  상태는 참고용일 뿐입니다.
- Runtime Session은 정규 Project Root에 속합니다. 해당 소유자만 상세 상태를 검사하고, 갱신하고,
  스크립트를 실행하거나 중지할 수 있습니다. 다른 프로젝트는 익명의 busy 상태만 볼 수 있습니다.
- 소유자 상태는 120초의 비활성 마감을 갱신합니다. 제한된 소유자 런타임
  작업은 활성 상태인 동안 비활성 만료를 일시 중지하고, 종료 상태의 스크립트
  결과를 반환한 후에만 마감을 갱신합니다. 제한 시간 초과, 설정 오류 또는 취소는
  갱신하지 않습니다. 실행이 진행되는 동안 약 30초마다 지터를 적용해 소유자 상태를
  폴링하세요.
- `max_run_seconds`는 양의 정수이며 기본값은 900초, 최댓값은 86,400초입니다. 한 시간걸리는 회귀 테스트는
  안전 여유를 위해 4,500초를 요청할 수 있습니다. 절대 마감은 중지되지 않습니다.
- 자연 종료, 명시적 중지, 시작 실패, 비활성 만료 또는 절대 만료는 Runtime Slot을 해제합니다.
- 시작 게이트 실패는 씬이 열리지 않게 합니다.
- C# 런타임 빌드는 열린 에디터의 일반 어셈블리 다시 불러오기를 일으킬 수 있습니다.
- `FENNARA_RUNTIME_SESSION_READY`와 `FENNARA_RUNTIME_ORIENTATION_NOTE` 두 마커 모두 5초 시작 기한 전에 나타나야 합니다. 하나라도 없으면 데몬은 프로세스를 종료하고 회수한 뒤 `startup_timeout`을 반환하며, 초기 성공을 반환해서는 안 됩니다.
- 관리 세션은 에디터 안에서 직접 실행한 씬이 아니라 별도 Godot 프로세스입니다.

<a id="runtimescript"></a>
### `runtime_script`

활성 관리 런타임 세션 안에서 제한된 GDScript 탐색 또는 입력 드라이버를 실행합니다.

정상 동작:

- 실행 중인 노드 검사, 발견 기록, 상태 대기, 매핑 또는 저수준 입력 전송, raycast, 기본 UI 상호작용, 프레임 캡처를 할 수 있습니다.
- `ctx.frame()`으로 저장되지 않은 뷰포트 Image를 모으고, `ctx.sheet()`로 스크린샷 작업자와 같은 호출자 제어 시트를 합성하며, 게임에 표시하지 않고 `ctx.output()`으로 파생 Image를 직접 게시할 수 있습니다.
- 스크립트가 끝나도 관리 씬은 다음 탐색을 위해 열린 상태로 유지될 수 있습니다.
- 가능한 경우 결과에 진단, 런타임 발견, 캡처 경로, 로그 경로, 세션 상태가 포함됩니다.

중요한 제한 및 실패:

- 유효한 활성 `runtime_session` 식별자가 필요합니다.
- 세션의 소유 Project Root만 프로브를 실행할 수 있습니다. 소유자가 아닌 경우 다른 프로젝트의 식별자가
  실제로 있는지 노출하지 않는 `runtime_session_not_owned_or_found`를 받습니다.
- 제한된 소유자 프로브는 실행되는 동안 비활성 만료를 일시 중지합니다. 반환된 종료
  상태의 스크립트 결과는 비활성 마감을 갱신하지만, 제한 시간 초과, 설정 오류 또는
  취소는 갱신하지 않습니다. 어떤 프로브도 절대 Runtime Lease를 연장하지 않습니다.
- 런타임 스크립트는 에디터 `@tool` 스크립트가 아니며 씬 편집 작업자로 사용할 수 없습니다.
- 잘못된 진단, 제한 시간 초과, 런타임 오류, 닫힌 세션, 사용할 수 없는 노드를 보고합니다.
- 탐색은 제한된 상태를 유지해야 하며 영구 게임플레이 자동화 프레임워크를 대체하지 않습니다.

<a id="scrapeeditor"></a>
### `scrape_editor`

사용자가 Godot 에디터에서 직접 씬을 실행한 뒤 작은 디버거 스냅샷을 읽습니다.

정상 동작:

- 반복 디버거 문제를 묶고 시끄러운 세부 정보 수를 제한합니다.
- 관리 런타임 세션이 소유하지 않은 에디터 실행 출력을 검사하는 데 도움이 됩니다.

중요한 제한 및 실패:

- 모든 에디터 UI 요소나 로그 줄을 읽는 것보다 의도적으로 범위가 좁습니다.
- `runtime_session`으로 시작한 씬에는 사용하지 마세요. 관리 런타임 로그가 더 완전합니다.
- 직접 실행한 항목이 없으면 유용한 디버거 상태가 없을 수 있습니다.

<a id="built-in-chat-tools-and-controls"></a>
## 내장 채팅 도구 및 컨트롤

<a id="readfile"></a>
### `read_file`

Godot 경로 처리를 사용해 프로젝트 범위 텍스트 파일과 지원 이미지를 읽습니다. `res://` 정규화나 이미지 처리가 중요할 때 유용합니다. 넓은 소스 탐색은 계속 일반 저장소 도구에 속합니다.

<a id="execcommand"></a>
### `exec_command`

활성 프로젝트 루트를 기본 작업 디렉터리로 하여 비대화형 명령 하나를 실행합니다.

정상 동작:

- 시간 및 출력 제한과 함께 표준 출력과 오류를 캡처합니다.
- 활성 프로젝트 루트 밖의 작업 디렉터리를 거부합니다.
- 큰 출력을 모델 대화에 유지하지 않아도 되도록 원시 데몬 측 영수증을 저장합니다.

중요한 제한 및 실패:

- 프로젝트 루트 제한과 승인 처리를 제공하지만 운영체제 샌드박스는 아닙니다.
- 대화형 터미널, PTY, 백그라운드 세션, 표준 입력 스트림 또는 임의 환경 구성을 제공하지 않습니다.
- 0이 아닌 종료, 제한 시간 초과, 출력 잘림을 보고합니다.

<a id="chat-controls"></a>
### 채팅 컨트롤

내장 채팅은 프로젝트를 변경하거나 런타임을 실행하는 도구 호출의 승인 모드를 지원합니다. 읽기 전용 검사는 즉시 실행할 수 있고 변경 또는 실행은 명시적인 승인을 요구할 수 있습니다. Full access는 해당 프롬프트를 제거하지만 강제 안전 검사를 우회하지 않습니다.

Godot 스크립트 에디터에서 선택한 코드는 **Add to Chat**으로 첨부할 수 있습니다. 전송 전에 작성기에 첨부 파일이 표시됩니다. `/provider`는 제공업체 설정을 열고 `/model`은 모델 선택을 엽니다. 이는 채팅 명령이며 MCP 도구가 아닙니다.

<a id="what-fennara-does-not-replace"></a>
## Fennara가 대체하지 않는 항목

다음에는 일반 개발 도구를 사용하세요.

- 넓은 저장소 검색 및 탐색
- 일반 텍스트 파일 읽기
- diff 및 버전 관리
- Godot 피드백이 필요하지 않은 편집
- 일반 셸 작업

답이 Godot의 이해, 가져오기, 직렬화, 렌더링, 검증 또는 프로젝트 실행에 의존할 때 Fennara를 사용하세요.
