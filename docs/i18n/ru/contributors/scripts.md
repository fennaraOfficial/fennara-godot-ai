Этот каталог содержит автоматизацию репозитория, общую для локальной разработки, package preview и рабочих процессов выпуска.

Скрипты должны быть небольшими, детерминированными и безопасными для запуска из корня репозитория, если в их справке не указано иное. Они не должны записывать относящееся к пользователю состояние за пределами репозитория.

<a id="version-scripts"></a>
## Скрипты версий

- `set-version.mjs`: обновляет файл `VERSION` репозитория, файл `VERSION` аддона, метаданные локальной рабочей области Rust, версии пакетов в lock-файле и константу версии плагина C++.
- `check-version.mjs`: проверяет, что эти версионируемые файлы по-прежнему синхронизированы.

Запускайте `check-version.mjs` в CI и перед упаковкой выпуска. Используйте `set-version.mjs` только при намеренном изменении версии Fennara.

<a id="packaging-scripts"></a>
## Скрипты упаковки

- `package-preview.mjs`: синхронизирует хранящиеся в репозитории полезные нагрузки аддона, затем собирает отдельные preview-архивы для платформ после того, как GDExtension и локальные бинарные файлы Rust уже собраны.
- `package-addon-all.mjs`: объединяет части аддона для платформ в итоговый архив аддона для всех платформ.
- `release-policy.mjs`: определяет минимальную совместимую опубликованную версию CLI для каждого канала выпуска.
- `write-release-manifest.mjs`: записывает `fennara-release-manifest-v<version>.json` на основе ресурсов выпуска и проверяет каждый указанный SHA-256.

Оба скрипта используют `.package-preview/` для временной подготовки и записывают ZIP-файлы в папку `dist/` в корне репозитория. Эти результаты игнорируются и не должны добавляться в коммиты.

Скрипты упаковки должны сохранять малый размер полезной нагрузки аддона. В частности, файлы рантайма CEF для Linux, такие как `libcef.so` и `fennara_cef_helper`, нельзя включать в `fennara-addon-*`. CEF устанавливается один раз в общий каталог данных приложения Fennara пользователя.

<a id="staging-release-scripts"></a>
## Скрипты промежуточного выпуска

- `write-staging-candidate.mjs`: создает точный идентификатор предварительного выпуска для одного pull request и зафиксированного исходного коммита.
- `validate-staging-build.mjs`: проверяет части аддона, архивы платформ, собранный аддон, манифест выпуска и CEF для Linux перед публикацией.
- `smoke-public-release.mjs`: загружает каждый опубликованный кандидат по не требующему аутентификации URL браузера и проверяет доверенный ресурс и хеши манифеста перед продвижением канала.
- `write-staging-pointer.mjs`: записывает небольшой указатель для pull request после хеширования точного манифеста выпуска.
- `check-staging-channel-advance.mjs`: отклоняет обратное или конфликтующее перемещение канала.
- `validate-staging-publish-bundle.mjs`: повторно проверяет итоговый набор артефактов без выполнения кода кандидата.
- `verify-published-assets.mjs`: сравнивает ожидаемые и загруженные имена ресурсов GitHub Release и значения SHA-256.

Эти скрипты поддерживают `.github/workflows/staging-release.yml`. Задания сборки кандидатов выполняются без учетных данных выпуска. Публиковать может только доверенное итоговое задание, и оно перемещает Git-ссылку соответствующего канала после загрузки и проверки точного выпуска.

<a id="linux-cef-scripts"></a>
## Скрипты CEF для Linux

- `prepare-linux-cef-sdk.mjs`: загружает и распаковывает закрепленный официальный CEF SDK Linux x64, используемый для сборки моста CEF в Linux.
- `prepare-linux-cef-runtime.mjs`: подготавливает отдельный ZIP-файл рантайма CEF для Linux, проверяет обязательные файлы, удаляет отладочные символы из подготовленных бинарных файлов ELF в Linux и может записать сформированный манифест `local/webview-runtimes/linux-cef.json` для упаковки выпуска.
- `check-linux-cef-runtime-release.mjs`: проверяет, что ресурсы выпуска содержат ZIP-файл рантайма CEF, указанный во включенном манифесте, и что его SHA-256 совпадает.
- `cef/linux/fennara_cef_helper.cpp`: исходный код небольшого вспомогательного процесса CEF, используемого при сборке вспомогательного средства рантайма из CEF SDK.

Скрипты CEF работают только с копиями файлов в промежуточном каталоге. Они не должны изменять дерево загруженного или исходного CEF SDK.

<a id="development-tests"></a>
## Тесты для разработки

- `test-run-scene-edit-script-inspect.mjs`: создает игнорируемый smoke-проект Godot в `temp/` и проверяет исследование импортированного `PackedScene`, ограничения контекста только для чтения, ошибку при отсутствии источника и поведение без сохранения с помощью собранного GDExtension для редактора.

<a id="documentation-localization"></a>
## Локализация документации

- `sync-doc-navigation.mjs`: добавляет хеши источника, стабильные якоря и компактный переключатель языка для той же страницы, не переводя текст.
- `check-doc-i18n.mjs`: проверяет полное покрытие локалей, актуальность источника, навигацию, якоря, структуру Markdown, защищенный код, URL-адреса и ссылки.
- `doc-i18n-lib.mjs`: содержит общий манифест локалей, нормализацию источника, формирование навигации и вспомогательные средства структуры.

Выполните:

```bash
node scripts/sync-doc-navigation.mjs
node scripts/check-doc-i18n.mjs
```

Локали и набор документов объявлены в `docs/i18n/languages.json`. Английский
язык остается каноническим. Переведенный текст должен быть написан на основе
английского источника, а не сформирован этими скриптами.

Обычная синхронизация обновляет навигацию и стабильные якоря, но сохраняет
существующие хеши источников. После непосредственного обновления всех девяти
переводов измененной английской страницы явно обновите только этот источник:

```bash
node scripts/sync-doc-navigation.mjs --accept-source docs/cli.md
```

Для нескольких проверенных источников параметр можно указать повторно. Не
подтверждайте источник, если его переведенный текст не был обновлен. CI запускает
`sync-doc-navigation.mjs --check` перед полным валидатором переводов.

<a id="ui-sync"></a>
## Синхронизация интерфейса

- `sync-chat-ui.mjs`: копирует `ui/chat/` в `godot_demo/addons/fennara/dist/`.

Каталог `godot_demo/addons/fennara/dist/` намеренно хранится в репозитории, поскольку ZIP-файлы выпущенного аддона должны содержать собранный webview чата. Вносите изменения в `ui/chat/`, запускайте скрипт синхронизации и добавляйте в один коммит исходные и сформированные ресурсы аддона.

<a id="runtime-sync"></a>
## Синхронизация рантайма

- `sync-runtime.mjs`: копирует `runtime/` в `godot_demo/addons/fennara/runtime/`.

Каталог `godot_demo/addons/fennara/runtime/` намеренно хранится в репозитории, поскольку ZIP-файлы выпущенного аддона должны содержать вспомогательные скрипты рантайма на стороне Godot. Вносите изменения в `runtime/`, запускайте скрипт синхронизации и добавляйте в один коммит исходные и сформированные ресурсы аддона.

<a id="guidance-sync"></a>
## Синхронизация инструкций

- `sync-guidance.mjs`: копирует компактные инструкции и загружаемые по запросу страницы знаний из `local/templates/` в `godot_demo/addons/fennara/ai/`, в соответствии с файлами, которые команды `fennara install` и `fennara update` записывают в пользовательские проекты.

Каталог `godot_demo/addons/fennara/ai/` намеренно хранится в репозитории, поскольку демонстрационный аддон повторяет структуру установленного аддона. Вносите изменения в `local/templates/`, запускайте скрипт синхронизации и добавляйте в один коммит исходные и сформированные инструкции аддона.

<a id="boundaries"></a>
## Границы

- Скрипты могут создавать результаты в `.package-preview/` и корневом `dist/`.
- Скрипты могут обновлять хранящиеся в репозитории сформированные полезные нагрузки, только если это является их явно заявленной задачей, как у `sync-chat-ui.mjs`, `sync-runtime.mjs`, `sync-guidance.mjs` или `set-version.mjs`.
- Скрипты не должны записывать кеш редактора Godot, локальные установки в каталогах данных приложений, загруженные ресурсы выпусков или результаты тестирования в виртуальных машинах в отслеживаемые исходные каталоги.
