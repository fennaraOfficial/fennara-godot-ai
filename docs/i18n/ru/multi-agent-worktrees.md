# Несколько агентов и рабочих деревьев Godot

<!-- fennara-doc-nav:start -->

Запускайте на одном компьютере несколько агентов программирования в отдельных репозиториях
или рабочих деревьях, не позволяя выбору цели одного агента перенаправить другого. Каждый
проект получает свой процесс и подключение Fennara MCP; все проекты совместно используют один демон
на пользователя.

```text
agent A -> MCP process A -- Project Binding A --\
                                                  shared daemon -> Godot editor A
agent B -> MCP process B -- Project Binding B --/              -> Godot editor B
```

Редактирование, исследование, валидация и вызовы снимков экрана могут выполняться параллельно.
Запуски игр под управлением демона сериализуются через один общий для компьютера Runtime Slot.

<a id="one-mcp-connection-per-project"></a>
## Одно MCP-подключение на проект

При запуске MCP-процесс выбирает один стабильный Project Root. Эта MCP Project Binding представляет собой каноническую
идентичность каталога файловой системы, содержащего `project.godot`, а не имя проекта или идентификатор
процесса Godot.

Используйте отдельный MCP-процесс и подключение для каждого репозитория или рабочего дерева. Одно
подключение может обслуживать несколько агентов, только если все они намеренно работают с одним проектом.
Инструменты Fennara не предоставляют селектор проекта для отдельного вызова, поэтому модель не может
случайно переключить процесс на другой проект.

Каждому проекту также нужен подключенный редактор Godot с включенной Fennara. Если редактор закроется
и подключится снова с другим идентификатором процесса, существующий MCP-процесс возобновит маршрутизацию,
когда тот же Project Root подключится заново.

<a id="how-a-process-chooses-its-project"></a>
## Как процесс выбирает проект

Среда MCP фиксирует рабочий каталог при запуске и однократно выбирает привязку в таком порядке:

1. `--project-path <path>` или `--project-path=<path>`.
2. `FENNARA_PROJECT_PATH`.
3. Ближайший предок каталога запуска, содержащий `project.godot`.
4. Устаревший непривязанный режим совместимости, если автоматический поиск не нашел проект Godot.

Пути командной строки и окружения являются явными утверждениями. Пустой, недоступный, отсутствующий,
не являющийся каталогом или проектом Godot, а также неподдерживаемый путь не дает MCP-серверу запуститься;
отката к другому проекту нет. Относительные пути разрешаются от зафиксированного каталога запуска. Если каталог
запуска MCP-хоста неясен, предпочитайте абсолютный путь.

Fennara не считывает неявно переменные рабочей области, специфичные для хоста. MCP-хост может передать свое
значение рабочей области в `--project-path` или `FENNARA_PROJECT_PATH`.

<a id="configure-a-project-bound-connection"></a>
## Настройка привязанного к проекту подключения

`fennara mcp-setup` остается глобальной и нейтральной к проекту. Ее запуск изнутри проекта не привязывает все
будущие MCP-процессы к этому проекту. Сохраните стабильный путь к программе запуска, а затем добавьте
привязку в конфигурацию проекта или рабочей области MCP-хоста.

Для конфигурации в формате JSON:

```json
{
  "mcpServers": {
    "fennara": {
      "command": "/absolute/path/to/fennara-mcp",
      "args": ["--project-path", "/absolute/path/to/worktree-a"],
      "env": {}
    }
  }
}
```

Или используйте окружение:

```json
{
  "mcpServers": {
    "fennara": {
      "command": "/absolute/path/to/fennara-mcp",
      "args": [],
      "env": {
        "FENNARA_PROJECT_PATH": "/absolute/path/to/worktree-a"
      }
    }
  }
}
```

Для TOML в стиле Codex:

```toml
[mcp_servers.fennara]
command = "/absolute/path/to/fennara-mcp"
args = ["--project-path", "/absolute/path/to/worktree-a"]
startup_timeout_sec = 30
tool_timeout_sec = 300
```

Настройте следующего агента в его собственной конфигурации проекта или рабочей области с
`/absolute/path/to/worktree-b`. Если хост надежно запускает отдельный MCP-процесс из каталога каждого проекта,
поиск предка может создать ту же привязку без явного пути.

<a id="mcp-host-boundaries"></a>
## Границы MCP-хостов

Поведение локальной для проекта конфигурации и каталога запуска зависит от хоста:

- Однопапочные рабочие области VS Code могут полагаться на документированный рабочий каталог
  дочернего процесса, но явная привязка к проекту все равно является самой ясной конфигурацией.
- Claude Code, Gemini CLI, Antigravity, Cline, Cursor, OpenCode, Kiro и Codex могут использовать конфигурацию
  проекта или рабочей области. Когда изоляция должна быть гарантирована, используйте явную привязку или
  документированный каталог запуска проекта.
- Claude Desktop и устаревшая конфигурация Windsurf/Cascade являются глобальными. Их запись Fennara по умолчанию
  остается непривязанной и не может автоматически изолировать проекты. Опытные пользователи могут создать
  отдельно именованные глобальные записи с разными явными путями, но должны выбирать правильную запись.

Автоматическая генерация локальной для проекта конфигурации и новая поддержка Windsurf/Devin Local не входят в этот
рабочий процесс.

<a id="start-and-verify-the-editors"></a>
## Запуск и проверка редакторов

Каждому рабочему дереву нужен свой редактор Godot с включенной Fennara. Редакторы без интерфейса могут
использовать разные порты Godot LSP, продолжая совместно использовать демон Fennara:

```bash
godot --editor --headless --path /absolute/path/to/worktree-a --lsp-port 6006
godot --editor --headless --path /absolute/path/to/worktree-b --lsp-port 6007
```

Порты LSP принадлежат Godot. Fennara продолжает использовать один общий демон на своем обычном локальном адресе.

Перед параллельной работой запустите `fennara_status` из каждого агента. Убедитесь, что он сообщает:

- режим маршрутизации `bound`
- ожидаемый источник привязки и канонический Project Root
- состояние привязанного редактора `connected`
- готовность файловой системы этого редактора

Если автоматический поиск не нашел проект, состояние сообщает `legacy_unbound` и предупреждение о параллельной работе.
В этом режиме совместимости сначала используется выбранная на панели MCP Target, а затем единственный
подключенный редактор. Не используйте непривязанное подключение для изолированной параллельной работы.

<a id="missing-and-duplicate-editors"></a>
## Отсутствующие и дублирующиеся редакторы

Допустимая Project Binding остается активной, когда ее редактор отсутствует. Вызовы инструментов возвращают
повторяемую ошибку `bound_project_not_connected`, пока этот Project Root не подключится снова; отката к цели на панели нет.

Два редактора, разрешающиеся в один Project Root, вызывают `ambiguous_project_binding`. Закройте дублирующийся редактор
или поместите его в отдельное рабочее дерево. Fennara не выбирает по идентификатору процесса, порядку подключения,
имени проекта или цели на панели.

Псевдонимы символических ссылок на один проект разрешаются в одну идентичность активной файловой системы.
Перенацеливание символической ссылки после запуска MCP не изменяет привязку; перезапустите MCP-процесс, чтобы
снова выполнить привязку.

<a id="serialized-runtime-sessions"></a>
## Сериализованные Runtime Session

Все проекты совместно используют один общий для компьютера Runtime Slot для запусков игр под управлением демона.
Когда другой проект запускает или уже выполняет сеанс, `runtime_session.start` возвращает успешный доменный
результат `busy` с `availability: "busy"`, `slot_acquired: false` и рекомендованным `retry_after_ms`. Он не раскрывает владельца,
идентификатор сеанса или процесса, сцену, журналы, место в очереди или ожидаемую продолжительность.

Очереди FIFO нет. Опрашивайте со случайным разбросом около рекомендованной задержки повтора и считайте каждый
`runtime_session.start` окончательным атомарным захватом. Свободное состояние лишь справочно, поскольку другой агент
может выиграть гонку после предварительной проверки.

Только Project Root владельца может просматривать, продлевать, выполнять скрипты или останавливать свой Runtime
Session. Запрос состояния владельцем продлевает 120-секундный срок по неактивности. Ограниченная операция
среды выполнения владельца приостанавливает истечение срока по неактивности на время выполнения и продлевает его только после
возврата итогового результата скрипта; истечение времени ожидания, ошибка подготовки или отмена его не продлевают. Пока запуск
продолжается, агенты должны опрашивать состояние владельца примерно каждые 30 секунд со случайным разбросом.

Абсолютный Runtime Lease по умолчанию равен 900 секундам. `max_run_seconds` принимает положительное целое число
до 86 400 секунд; например, для регрессии продолжительностью около часа можно запросить 4 500 секунд с запасом. Абсолютный
крайний срок никогда не приостанавливается. Естественное завершение, явная остановка, ошибка запуска, неактивность или
абсолютное истечение срока останавливает или завершает игру и освобождает Runtime Slot.

<a id="safe-multi-agent-checklist"></a>
## Контрольный список безопасной работы нескольких агентов

1. Создайте отдельный репозиторий или рабочее дерево для каждого проекта.
2. Установите Fennara и откройте по одному редактору Godot для каждого Project Root.
3. Настройте по одному привязанному к проекту MCP-процессу на проект.
4. Запустите `fennara_status` от каждого агента и проверьте его канонический корень.
5. Позвольте редактированию, исследованию, ограниченной валидации сцен и автономным
   снимкам экрана выполняться параллельно.
6. Для игровых тестов опрашивайте и повторяйте не являющиеся ошибками результаты `busy`; пока идет сеанс-
   победитель, поддерживайте его аренду запросами состояния владельца.
