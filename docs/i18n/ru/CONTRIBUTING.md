Спасибо, что помогаете улучшать Fennara Godot AI.

<a id="good-contributions"></a>
## Полезный вклад

- Исправления документации
- Воспроизводимые исправления ошибок
- Исправления совместимости с платформами
- Улучшения сборки и упаковки
- Небольшие улучшения ясности настройки

<a id="design-discussion-required"></a>
## Требуется обсуждение дизайна

Создайте issue или discussion перед началом работы над следующими изменениями:

- новые инструменты MCP
- изменения схем инструментов
- изменения процесса выпуска
- крупные изменения архитектуры
- изменения, влияющие на формируемые инструкции проекта

<a id="pull-requests"></a>
## Pull request

- Делайте pull request небольшими и целенаправленными.
- Объясняйте, что изменилось и почему.
- Объясняйте, как вы проверили изменение.
- Для видимых изменений интерфейса или отображения документации добавляйте снимки экрана или записи.
- Не включайте несвязанные изменения форматирования или очистку.
- Не вставляйте в issue или pull request большие автоматически сформированные описания.

<a id="commit-and-pr-titles"></a>
## Заголовки коммитов и pull request

Используйте стиль Conventional Commits:

```text
fix(daemon): handle missing daemon status
docs(setup): clarify setup steps
ci(actions): add public pull request checks
```

Распространенные типы:

- `feat`: функция, видимая пользователю
- `fix`: исправление ошибки
- `docs`: документация
- `ci`: GitHub Actions и автоматизация
- `build`: сборка или упаковка
- `refactor`: изменение структуры кода без изменения поведения
- `test`: тесты
- `chore`: обслуживание

<a id="project-boundaries"></a>
## Границы проекта

Fennara должна оставаться независимой от конкретной игры. Избегайте API или инструкций, которые предполагают определенные элементы игры: управление, цели, экономику, инвентарь, бой, поиск пути, задания или последовательность действий в интерфейсе.

Агенты должны исследовать реальные сцены, скрипты, ресурсы, настройки, состояние выполнения, диагностику и снимки экрана проекта Godot, а затем комбинировать универсальные инструменты Fennara для этого проекта.

<a id="documentation-translations"></a>
## Переводы документации

Английский язык является каноническим источником. Сначала исправьте английскую
версию, затем обновите все затронутые локали. Набор переводимых документов и
метаданные локалей находятся в `docs/i18n/languages.json`.

- Полностью прочитайте английскую страницу и напишите перевод самостоятельно. Не используйте сервисы массового машинного перевода или скрипты для создания текста.
- Оставляйте без изменений блоки кода, встроенный код, команды, пути, ключи конфигурации, URL-адреса и названия продуктов.
- Сохраняйте маркер источника и явные английские псевдонимы якорей, которыми управляют скрипты документации.
- Не помечайте перевод как проверенный носителем языка, если его не проверил свободно владеющий языком рецензент.
- Не переводите юридические тексты, внутренние запросы агентов, формируемые инструкции проекта, файлы поставщиков или тестовые фикстуры как самостоятельные источники.

После изменения канонической или переведенной документации выполните:

```bash
node scripts/sync-doc-navigation.mjs
node scripts/check-doc-i18n.mjs
```

Эти команды поддерживают метаданные навигации и проверяют структуру. Они не
создают переведенный текст.

Обычная синхронизация навигации сохраняет все существующие хеши источников.
После изменения английского источника самостоятельно обновите эту страницу во
всех девяти переведенных локалях, а затем явно подтвердите только этот
канонический источник:

```bash
node scripts/sync-doc-navigation.mjs --accept-source docs/cli.md
node scripts/check-doc-i18n.mjs
```

Повторите `--accept-source <path>` для каждой английской страницы, переводы
которой были проверены и обновлены. Никогда не подтверждайте хеш источника, пока
все девять переводов не будут передавать новый смысл.
