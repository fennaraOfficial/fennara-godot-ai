На этой странице приведены краткие ответы и ссылки на подробные справочники.

| Вопрос | Краткий ответ |
| --- | --- |
| Нужен ли ключ провайдера? | Только для облачного провайдера во встроенном чате |
| Можно ли вместо этого использовать внешнее MCP-приложение? | Да, оно использует собственную учетную запись модели |

<a id="is-fennara-only-a-code-generator"></a>
## Fennara является только генератором кода?

Нет. Fennara является рабочим процессом агента, учитывающим особенности Godot. Она может работать с файлами проекта, сценами, диагностикой, ошибками времени выполнения, снимками экрана и контекстом редактора Godot.

<a id="is-fennara-just-another-godot-mcp-command-server"></a>
## Fennara является еще одним командным MCP-сервером для Godot?

Нет. MCP является одним из способов использовать Fennara из таких приложений, как Codex, Claude, Cursor, Gemini и Antigravity. У Fennara также есть необязательная встроенная панель чата. Основная идея продукта заключается в цикле обратной связи Godot: диагностика, проверка, ошибки времени выполнения, снимки экрана и структурированные результаты инструментов позволяют агентам исправлять ошибки.

<a id="does-fennara-replace-godot-knowledge"></a>
## Заменяет ли Fennara знания о Godot?

Нет. Fennara не пытается сделать Godot необязательным. Она разработана, чтобы ИИ-агенты сверялись с настоящим движком Godot.

<a id="how-should-i-install-fennara"></a>
## Как установить Fennara?

В Windows и Linux добавьте аддон, откройте панель Fennara и нажмите **Set Up
Fennara** или установите из терминала. В macOS установите через CLI, чтобы
избежать уведомления безопасности, которое может появиться после ручной
распаковки ZIP-файла аддона, загруженного через браузер. Оба способа описаны
в разделе [Настройка](setup.md).

<a id="why-does-macos-say-it-cannot-verify-libfennaramacoseditor"></a>
## Почему macOS сообщает, что не может проверить `libfennara.macos.editor`?

Аддон из выпуска содержит нативную библиотеку, которая в настоящее время
не нотарифицирована Apple. Когда ZIP-файл аддона загружается через браузер и
распаковывается вручную, Finder может передать этой библиотеке метаданные
карантина, что приводит к появлению уведомления macOS.

Чтобы избежать его, используйте [установку через CLI](setup.md#install-from-the-terminal-recommended-on-macos).
Если уведомление уже появилось, закройте Godot, удалите скопированную вручную
папку `addons/fennara/`, установите CLI и выполните `fennara install` из каталога
проекта. CLI устанавливает тот же аддон без прохождения через карантин браузера
и Finder.

<a id="do-i-need-a-chat-provider-api-key"></a>
## Нужен ли ключ API провайдера чата?

Только если вы хотите использовать облачного провайдера во встроенной панели чата Fennara. Внешние клиенты MCP используют собственную конфигурацию модели и приложения и могут вызывать инструменты Fennara MCP без добавления ключа провайдера в чат Fennara.

Встроенный чат также может использовать локальный Ollama или LM Studio без
облачного ключа API. См. [Провайдеры встроенного чата](providers.md).

<a id="why-does-the-dock-ask-for-a-provider-if-i-already-ran-mcp-setup---claude"></a>
## Почему панель запрашивает провайдера, если я уже выполнил `mcp-setup --claude`?

Команда `fennara mcp-setup --claude` подключает Claude к инструментам Godot MCP в Fennara. Она не подключает встроенную панель Fennara к Claude и не передает чату Fennara вашу подписку Claude.

Используйте Claude Code или Claude Desktop для внешнего рабочего процесса MCP. Настраивайте отдельного провайдера, только если хотите общаться внутри панели Fennara в Godot. См. [MCP-приложения и встроенный чат](chat-vs-mcp.md).

<a id="what-are-provider-and-model"></a>
## Что такое `/provider` и `/model`?

Это slash-команды во встроенной панели чата Fennara. `/provider` открывает выбор провайдера. `/model` открывает выбор модели. Это сокращения интерфейса, а не внешние инструменты MCP и не текст, отправляемый модели. См. [Slash-команды встроенного чата](slash-commands.md).

<a id="does-fennara-send-my-godot-project-to-a-fennara-server"></a>
## Отправляет ли Fennara мой проект Godot на сервер Fennara?

Нет. При обычном использовании OSS клиент MCP, демон и аддон Godot работают
локально. Встроенный чат отправляет запросы к модели только настроенному вами
провайдеру, например OpenAI, Anthropic, OpenRouter, Ollama Cloud, DeepSeek, Z.AI,
Moonshot AI, Kimi For Coding, MiniMax или локальному серверу Ollama/LM Studio.

<a id="which-project-receives-mcp-tool-calls-if-multiple-godot-editors-are-open"></a>
## Какой проект получает вызовы инструментов MCP, если открыто несколько редакторов Godot?

Привязанный к проекту MCP-процесс направляет каждый вызов в подключенный редактор
для своего канонического Project Root. Для агентов, параллельно работающих в разных репозиториях
или рабочих деревьях, используйте по одному MCP-процессу и подключению для каждого проекта.

Непривязанный MCP-процесс сохраняет поведение совместимости: демон использует выбранную
на панели цель MCP Target, а затем единственный подключенный редактор. Перед параллельной
работой запустите `fennara_status` и убедитесь, что указаны режим маршрутизации `bound` и ожидаемый
корень. Сеансы встроенного чата остаются привязанными к редактору, который открыл чат. См.
[Несколько агентов и рабочих деревьев](multi-agent-worktrees.md).

<a id="can-several-agents-run-their-games-at-the-same-time"></a>
## Могут ли несколько агентов одновременно запускать свои игры?

Нет, если используются Runtime Session под управлением демона. Редактирование,
исследование, ограниченная валидация сцен и автономные снимки экрана могут
выполняться параллельно, но все проекты совместно используют один Runtime Slot
для интерактивных управляемых запусков игр. Проигравший запрос запуска получает
обычный анонимный результат `busy`, поэтому агент может опрашивать со случайным
разбросом и повторять попытку, не мешая текущему запуску. Проект-владелец
продлевает крайний срок по неактивности, опрашивая состояние, пока выполняется
запуск; абсолютный срок аренды никогда не сдвигается.

<a id="why-does-linux-install-a-separate-cef-runtime"></a>
## Почему в Linux устанавливается отдельный рантайм CEF?

Встроенный чат в Linux использует внеэкранный рендеринг CEF. Полезная нагрузка
CEF велика, поэтому Fennara устанавливает ее один раз в каталог данных приложения
Fennara пользователя, вместо того чтобы копировать в аддон каждого проекта Godot.

<a id="is-the-addon-supposed-to-contain-libcefso"></a>
## Должен ли аддон содержать `libcef.so`?

Нет. `libcef.so`, ресурсы CEF, пакеты локалей и вспомогательная программа CEF
должны находиться в общем рантайме CEF для Linux. Аддон должен содержать только
файлы аддона Godot, бинарные файлы GDExtension, файлы интерфейса чата и небольшие
встроенные вспомогательные программы, такие как ripgrep.

<a id="what-if-the-built-in-chat-webview-cannot-start"></a>
## Что делать, если не удается запустить webview встроенного чата?

Инструменты Fennara MCP продолжат работать. Системный webview нужен только
необязательной панели чата внутри редактора. В Windows установите Microsoft Edge
WebView2 Runtime, если `fennara doctor` сообщает, что он отсутствует. В macOS
WKWebView предоставляется системным WebKit.framework. В Linux выполните
`fennara update`, чтобы установить или восстановить управляемый выпуском рантайм
CEF.

Также можно использовать параметр Chat Settings **Open chat in my system browser next
time**. При этом сохраняются тот же встроенный чат Fennara и настройки провайдера,
но интерфейс открывается через локальный демон в системном браузере, а не во
встроенном webview Godot. Перезапустите Godot после изменения настройки.

<a id="does-opening-chat-in-my-browser-use-claude-or-my-mcp-app"></a>
## Использует ли открытый в браузере чат Claude или мое MCP-приложение?

Нет. Отображение в браузере является только выбором интерфейса и рантайма
встроенного чата Fennara. Он по-прежнему использует провайдера, выбранного
в настройках чата Fennara. Команда `fennara
mcp-setup --claude` и аналогичные команды настраивают внешние MCP-приложения,
они не настраивают модель встроенного чата.

<a id="does-fennara-update-rewrite-mcp-app-config"></a>
## Перезаписывает ли `fennara update` конфигурацию MCP-приложения?

Нет. `fennara update` при необходимости обновляет установленный CLI, аддон
проекта, локальный пакет рантайма, сформированные инструкции проекта и ресурсы
рантайма под управлением платформы. Выполняйте `fennara mcp-setup` повторно
только для настройки или восстановления конфигурации MCP-приложения.

<a id="where-does-chat-history-live"></a>
## Где хранится история чата?

История чата хранится локально демоном и относится к текущему проекту Godot.
Ключи провайдеров и URL-адреса локальных провайдеров также хранятся локально
демоном вне проекта Godot.

<a id="what-should-agents-use-fennara-tools-for"></a>
## Для чего агентам следует использовать инструменты Fennara?

Используйте Fennara для обратной связи с учетом особенностей Godot: деревьев
сцен, измененных свойств узлов и ресурсов, диагностики, проверки, сеансов
выполнения, снимков экрана и состояния отладчика редактора. Клиенты MCP
по-прежнему должны использовать собственные обычные инструменты чтения и поиска
файлов, если не требуется инструмент, специфичный для Fennara.
