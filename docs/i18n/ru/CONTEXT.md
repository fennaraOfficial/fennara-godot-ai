Этот файл определяет общие термины, используемые в документации Fennara, issue, примечаниях к выпускам и инструкциях для агентов.

<a id="product-terms"></a>
## Термины продукта

**Fennara**

Среда для агентов, учитывающая особенности Godot, из этого репозитория. Fennara подключает инструменты ИИ к реальной обратной связи Godot, включая диагностику, проверку сцен, ошибки времени выполнения, снимки экрана и инструкции проекта.

**Godot Addon**

Устанавливаемый плагин, копируемый в пользовательский проект Godot по пути `res://addons/fennara/`. Он отвечает за интерфейс панели, предназначенные для Godot инструменты исследования, нативную библиотеку GDExtension, упакованные ресурсы интерфейса чата, вспомогательные скрипты рантайма и локальную для проекта версию аддона.

**Fennara CLI**

Команда `fennara`, установленная на компьютере пользователя. Она выполняет установку, обновление, самообновление CLI, проверки doctor, настройку MCP-приложений, предупреждения о требованиях webview, проверки настройки C# и формирование инструкций проекта.

**Local Package**

ZIP-файл выпуска, содержащий локальные исполняемые файлы Fennara, такие как MCP-сервер, демон, бинарные файлы рантайма и запускающие бинарные файлы для одной платформы и архитектуры.

**Project Guidance**

Сформированные файлы инструкций, размещенные в проекте Godot, включая `AGENTS.md` и направляемые справочные материалы в `addons/fennara/ai/`, чтобы ИИ-агенты для программирования знали, когда и как использовать Fennara.

<a id="mcp-terms"></a>
## Термины MCP

**Fennara MCP Server**

Локальный MCP-сервер stdio, запускаемый ИИ-приложением для программирования, таким как Claude Code, Cursor, Cline, Gemini CLI или другой клиент MCP. Он предоставляет этому внешнему приложению инструменты Fennara.

**MCP App**

Внешнее ИИ-приложение, настроенное командой `fennara mcp-setup`. Настройка MCP-приложения определяет, какое внешнее приложение может вызывать инструменты Fennara. Она не выбирает модель для встроенного чата Fennara.

**MCP Target**

Проект Godot, выбранный в настоящее время для получения вызовов Fennara MCP.

**Tool Schema**

Предназначенное для модели описание инструмента Fennara MCP, включая аргументы, ограничения и примечания по рабочему процессу.

**Tool Result Envelope**

Краткий, предназначенный для модели результат, возвращаемый после вызова инструмента. Результаты Fennara должны объяснять состояние, важные выводы и следующий полезный контекст без вывода ненужных необработанных данных.

<a id="built-in-chat-terms"></a>
## Термины встроенного чата

**Built-In Chat**

Собственный интерфейс чата Fennara внутри аддона Godot или системного браузера. Он отделен от внешних MCP-приложений. Пользователь может настроить Claude Code для MCP, а для встроенного чата выбрать другого провайдера или модель.

**Chat Surface**

Режим отображения встроенного чата. Во встроенном режиме используется нативный webview панели Godot. В браузерном режиме тот же интерфейс обслуживается локальным демоном и открывается в системном браузере.

**Chat Provider**

Серверная система, способная формировать ответы встроенного чата, например OpenAI, Anthropic,
OpenRouter, Ollama Cloud, DeepSeek, Z.AI, Moonshot AI, Kimi For Coding, MiniMax,
локальный Ollama или LM Studio.

**Model Ref**

Идентификатор модели с указанием провайдера, выбранный во встроенном чате. Slash-команды, такие как `/provider` и `/model`, помогают пользователям подключать провайдеров и выбирать ссылки на модели.

**Provider Connection**

Локальные настройки и состояние аутентификации провайдера чата, которыми управляет демон, включая ключи API или локальные базовые URL-адреса. Секреты провайдера должны оставаться в локальном хранилище под управлением демона, а не в проекте Godot.

**Generation Trace**

Сохраненные метаданные формирования ответа встроенного чата, связывающие сообщения ассистента, вызовы инструментов, выбор провайдера и модели, использование и журналы стоимости с процессом формирования, который их создал.

<a id="runtime-and-webview-terms"></a>
## Термины рантайма и webview

**Fennara Daemon**

Локальная служба, которая связывает вызовы MCP и запросы встроенного чата с аддоном Godot, хранит локальное состояние рантайма и обслуживает размещенные демоном маршруты чата, такие как `/chat/`.

**Runtime Session**

Сеанс выполнения Godot под управлением демона, используемый для исследования времени выполнения, журналов, проверки, снимков экрана и будущих рабочих процессов с работающими сценами.

**Godot Snapshot**

Обратимый снимок состояния проекта, сделанный перед поддерживаемым Fennara ходом, который может изменять файлы. Подготовка снимка должна завершиться до сохранения пользовательского хода, чтобы неудачная подготовка не оставляла необработанные запросы.

**Webview Runtime**

Поддержка платформы, необходимая для отображения встроенного чата в Godot или рядом с ним. Windows использует WebView2, macOS использует WebKit/WKWebView, а Linux использует общий рантайм CEF, установленный в каталоге данных приложения Fennara.

**Shared Linux CEF Runtime**

Внешняя полезная нагрузка рантайма CEF для Linux, используемая webview чата в Linux. Она устанавливается один раз в каталоге данных приложения Fennara пользователя и не должна включаться в каждый ZIP-файл аддона Godot.

<a id="release-terms"></a>
## Термины выпуска

**Release Manifest**

JSON-ресурс с именем `fennara-release-manifest-v<version>.json`. Он сопоставляет ресурсы выпуска платформам, записывает хеши SHA-256, объявляет общие ресурсы рантайма и задает `minimum_cli_version`.

**Minimum CLI Version**

Минимальная версия CLI `fennara`, которой разрешено использовать манифест выпуска.
Если выпуск требует новой логики установки или обновления, обновите его канал
в `scripts/release-policy.mjs`. Средство записи манифеста применяет эту политику
после проверки идентификатора выпуска, рабочие процессы не выбирают значение.

**Latest Release**

Указатель GitHub Latest Release на точный версионированный выпуск. Установщики
и обычные обновления разрешают этот указатель через API GitHub. Fennara не
использует буквальный тег или выпуск `latest`. Обновление исходных файлов после
публикации не изменяет ресурсы выпуска. Уже опубликованные ресурсы манифеста
необходимо заменять явно.
