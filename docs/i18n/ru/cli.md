Используйте CLI, если предпочитаете терминал, вам нужны диагностика или
восстановление либо вы хотите автоматизировать установку точной версии.

> [!TIP]
> CLI является рекомендуемым способом установки в macOS. Он позволяет избежать
> уведомления системы безопасности macOS, которое может появиться, когда
> скачанный в браузере ZIP-архив дополнения распаковывается вручную, а его
> нативная библиотека наследует карантин Finder.

<a id="common-flow"></a>
## Обычный процесс

```bash
cd path/to/your-godot-project
fennara install
```

Используйте `fennara doctor`, когда нужно проверить или исправить локальную
установку.

Обычный процесс работы в Godot описан в разделе [Настройка](setup.md).
Эта страница служит справочником по командам терминала.

<a id="install-the-cli"></a>
## Установка CLI

Windows:

```powershell
irm https://raw.githubusercontent.com/fennaraOfficial/fennara-godot-ai/main/install.ps1 | iex
```

macOS и Linux:

```bash
curl -fsSL https://raw.githubusercontent.com/fennaraOfficial/fennara-godot-ai/main/install.sh | sh
```

Если дополнение, вручную распакованное в macOS, уже вызывает уведомление для
`libfennara.macos.editor`, закройте Godot и удалите вручную скопированную папку
`addons/fennara/`, прежде чем запускать `fennara install`. В противном случае
CLI сохраняет существующее полное дополнение.

Если команда `fennara` недоступна сразу, откройте новый терминал, затем проверьте
установку:

```bash
fennara --version
fennara doctor
```

CLI устанавливается отдельно для каждого пользователя. Дополнения проектов
остаются внутри соответствующих проектов Godot, а общие программы запуска,
версионные среды выполнения, записи операций, журналы и CEF для Linux находятся
в каталоге данных приложения Fennara:

```text
Windows: %LOCALAPPDATA%\Fennara
macOS: ~/Library/Application Support/Fennara
Linux: ~/.local/share/fennara
```

<a id="command-summary"></a>
## Сводка команд

| Команда | Назначение |
| --- | --- |
| `fennara install` | Установить или принять существующее дополнение проекта и соответствующие ему локальные компоненты |
| `fennara update` | Обновить проект и его локальные компоненты |
| `fennara doctor` | Проверить или исправить локальную установку |
| `fennara diagnostics` | Показать очищенный отчет об операции |
| `fennara mcp-setup` | Подключить внешнее приложение MCP |
| `fennara prepare-export` | Удалить автозагрузку Fennara перед экспортом в CI без аддона |
| `fennara recover` | Восстановиться после прерванного нативного обновления |
| `fennara self-update` | Обновить только установленный CLI |

Выполните `fennara --help`, чтобы увидеть сводку команд установленной версии.
Список поддерживаемых целевых приложений MCP можно получить командой
`fennara mcp-setup --help`.

<a id="install-a-project"></a>
## Установка проекта

Запустите внутри каталога, содержащего `project.godot`:

```bash
fennara install
```

Или укажите проект явно:

```bash
fennara install --project path/to/project
```

Без `--version` CLI выбирает манифест текущего выпуска. Если важна
воспроизводимость, укажите точный выпуск:

```bash
fennara install --project path/to/project --version <version>
```

Установка выполняется одним из двух безопасных способов:

- Если полного дополнения нет, CLI скачивает и проверяет выбранный выпуск,
  устанавливает `addons/fennara`, соответствующие локальные компоненты и
  записывает инструкции Fennara для проекта.
- Если полное дополнение уже существует, CLI считывает его `VERSION`, проверяет
  библиотеку для текущей платформы и устанавливает компоненты под управлением
  CLI именно этой версии. Каталог дополнения проекта остается без изменений.
  Явное значение `--version` должно совпадать с существующим дополнением.

<a id="prepare-an-addon-free-ci-export"></a>
## Подготовка экспорта в CI без аддона

Если `addons/fennara/` исключается из рабочей копии CI, удалите постоянную
автозагрузку среды выполнения Fennara до запуска Godot:

```bash
fennara prepare-export --project path/to/project
godot --headless --path path/to/project --export-release "Preset"
```

Команда изменяет только запись `_fennara_game_capture` в `project.godot`. Она
сохраняет остальные автозагрузки и настройки, и ее можно безопасно запускать
повторно. Этот шаг необходимо выполнить до запуска Godot, потому что при запуске
проекта Godot проверяет пути автозагрузки раньше, чем могут выполниться плагины
редактора или экспорта. Вместо этого CI может установить аддон Fennara до
запуска Godot.

<a id="update-a-project"></a>
## Обновление проекта

Для обычного обновления через терминал закройте Godot для этого проекта и
выполните:

```bash
fennara update --project path/to/project
```

Без `--version` CLI считывает идентификатор установленного дополнения.
Стабильные дополнения используют последний выпуск GitHub, а тестовые дополнения
используют только свой канал `pr-<number>`. Выбранное значение сразу фиксируется
как одна точная версия, в том числе на время самостоятельной замены CLI. Затем
CLI проверяет ресурсы выпуска, обновляет дополнение и версионные локальные
компоненты, обновляет инструкции проекта и проверяет предварительное условие
для веб-представления на этой платформе. Используйте `--version <version>`,
чтобы явно выбрать точный выпуск.

Параметр `--no-self-update` предназначен для управляемой автоматизации или
продолжения после того, как CLI уже был заменен. Не используйте его, чтобы
обойти требование выпуска к минимальной версии CLI.

> [!IMPORTANT]
> При обновлении Fennara v0.3.8 или более ранней версии сначала один раз
> переустановите CLI с помощью команды для своей платформы из раздела
> [Настройка](setup.md#install-from-the-terminal-recommended-on-macos), а затем
> выполните `fennara update`. Эти версии CLI обращаются к удаленному тегу
> выпуска и не могут обнаруживать текущие выпуски. Переустановка CLI не удаляет
> дополнение проекта или настройки.

> [!IMPORTANT]
> В macOS перед обновлением Fennara v0.3.11 один раз переустановите CLI. Эта
> версия CLI отклоняет существующий пакет фреймворка до перехода к
> самостоятельному обновлению. Переустановка заменяет только CLI и сохраняет
> дополнение проекта и настройки.

<a id="prepare-while-godot-is-open"></a>
### Подготовка при открытом Godot

Кнопка обновления в редакторе использует подготовительную форму:

```bash
fennara update --prepare --project path/to/project
```

Подготовка скачивает, проверяет и надежно размещает дополнение во временном
хранилище. Она не закрывает Godot, не заменяет активное дополнение, не
переключает активный манифест среды выполнения и не перезапускает фоновую
службу. Панель Godot наблюдает за квитанцией операции и запрашивает
подтверждение пользователя перед запуском отделенного этапа закрытия, замены,
повторного открытия и проверки. Панель передает уже обнаруженную точную версию,
поэтому изменение указателя не может повлиять на выполняющееся обновление.

Fennara поддерживает одну активную версию общей среды выполнения одновременно.
Активация блокируется, если к общей фоновой службе остается подключен другой
редактор Godot с Fennara. Закройте другой редактор и повторите попытку.
Предыдущая локальная версия и указатель среды выполнения остаются доступными
для восстановления без доступа к сети.

`--prepare` является низкоуровневым примитивом для интеграции с Godot.
Пользователи терминала обычно запускают `fennara update`, предварительно закрыв
Godot.

<a id="recover-an-interrupted-update"></a>
## Восстановление после прерванного обновления

Если обновленное дополнение не может загрузиться до этапа отображения панели
восстановления, закройте Godot и выполните:

```bash
fennara recover --project path/to/project
```

CLI восстанавливает только операции, находящиеся в состоянии, допускающем
восстановление. Он возвращает предыдущее дополнение, общие программы запуска и
активный манифест среды выполнения, затем пытается снова открыть записанный
исполняемый файл Godot. Когда служба поддержки сообщает идентификатор операции,
выберите конкретную транзакцию:

```bash
fennara recover --project path/to/project --operation <operation-id>
```

Завершенные, только подготовленные и уже откаченные операции отклоняются.

<a id="inspect-health-and-failures"></a>
## Проверка состояния и сбоев

Команда `doctor` сообщает обнаруженную платформу, структуру данных приложения,
активную версию, программы запуска, среды выполнения, состояние фоновой службы
и предварительное условие для веб-представления:

```bash
fennara doctor
```

Если она сообщает о запущенной фоновой службе или среде выполнения MCP старше,
чем версия в `current.json`, перезапустите Godot или соответствующее приложение
MCP, чтобы оно запустило выбранную среду выполнения.

Используйте `--repair`, чтобы заново создать отсутствующие базовые каталоги
данных приложения. В Linux эта команда также очищает устаревшие профили
процессов CEF и исправляет маркер текущей среды выполнения, когда полная
управляемая среда уже установлена:

```bash
fennara doctor --repair
```

Операции установки, обновления, восстановления и самостоятельного обновления
записывают долговечное состояние и события. Чтобы показать самый новый
очищенный отчет, выполните:

```bash
fennara diagnostics
```

Для более старой операции или машиночитаемого вывода:

```bash
fennara diagnostics --operation <operation-id>
fennara diagnostics --operation <operation-id> --json
```

Отчеты содержат стабильные коды ошибок, этапы, версии компонентов, имена
выбранных ресурсов и результаты проверки хешей. В них скрываются пути проекта,
домашнего каталога и данных приложения Fennara, учетные данные, токены
предъявителя и параметры запросов URL. В них не включаются сообщения чата,
ключи поставщиков и содержимое файлов проекта.

<a id="configure-an-external-mcp-app"></a>
## Настройка внешнего приложения MCP

В панели чата Godot эти команды доступны в разделе **Chat Settings > MCP Apps**.
Кнопка Set Up запрашивает у локальной фоновой службы запуск установленного CLI,
поэтому панель и терминал используют одну реализацию настройки и резервного
копирования.

Выполните `fennara mcp-setup --help`, чтобы выбрать поддерживаемое целевое
приложение. После изменения конфигурации перезапустите приложение MCP. Эта
команда подключает внешнее приложение к серверу Fennara MCP. Она не выбирает
поставщика модели для встроенной панели чата Godot. Список целевых приложений,
расположения конфигурации и примеры ручной настройки приведены в разделе
[Настройка MCP](mcp-setup.md).

<a id="update-only-the-cli"></a>
## Обновление только CLI

Обычные обновления проекта автоматически обрабатывают самостоятельное
обновление CLI. Чтобы обновить только установленный CLI:

```bash
fennara self-update
fennara self-update --version <version>
```

Без `--version` самостоятельное обновление сохраняет активный канал установки:
стабильная установка использует последний выпуск GitHub, а тестовая только
записанный для нее канал PR.

Тестовый канал никогда не переходит в стабильный автоматически. Чтобы намеренно
выйти из тестового канала, закройте Godot и выполните
`fennara update --version <stable-version> --project <path>`. Точный стабильный
выпуск будет проверен до изменения общей активной версии.

Используйте эту команду по запросу службы поддержки или когда обновление проекта
сообщает, что установленный CLI слишком стар для безопасного продолжения.

<a id="automation-guidance"></a>
## Рекомендации по автоматизации

- Передавайте `--project`, а не полагайтесь на текущий каталог.
- Фиксируйте `--version`, если сборка должна быть воспроизводимой.
- При сбое сохраняйте выведенные идентификатор операции и путь к журналу.
- Для структурированных отчетов используйте `fennara diagnostics --operation <id> --json`.
- Не редактируйте вручную `current.json`, каталоги версий, квитанции обновления
  и каталоги подготовленных дополнений.
- Не запускайте обычное обновление с заменой дополнения, пока этот проект открыт
  в Godot. Используйте процесс обновления в редакторе или сначала закройте Godot.
