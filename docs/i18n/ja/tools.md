Fennara はコーディングエージェントへ、Godot を認識した調査、編集、検証、スクリーンショット、ランタイムフィードバックを提供します。通常のリポジトリツールやシェルツールを置き換えるのではなく、それらを補完します。

このページでは、各ツールでできること、呼び出しの成功が意味すること、重要な制約または失敗事例を説明します。正確な引数、結果フィールド、制限、エージェント向け指示については、実際のツールスキーマが引き続き信頼できる唯一の情報源です。インストール済みプロジェクトには、簡潔なガイドラインと必要時に参照する知識も `addons/fennara/ai/` に追加されます。

<a id="tool-surfaces"></a>
## ツールの利用面

Codex、Claude Code、Cursor、Gemini などの外部 MCP クライアントは、ローカルの `fennara-mcp` プロセスを通して接続します。各クライアントは自身のモデルアカウントと通常のファイル、検索、差分、シェルツールを Fennara とともに使用します。

内蔵 Fennara チャットは、同じデーモンと Godot ブリッジを使用します。同じ Godot ツールを呼び出せるほか、プロジェクト単位の `read_file` および `exec_command` ツールも提供します。プロバイダーとモデルの設定は内蔵チャットに属し、MCP サーバーには属しません。

`fennara_status` は外部 MCP クライアントで利用できます。内蔵チャットは、接続状態とアクティブプロジェクトの状態をデーモンからすでに受け取っています。

<a id="typical-workflow"></a>
## 一般的な作業手順

1. 外部 MCP クライアントを使用する場合は、接続中のプロジェクトを確認します。
2. 関係するシーン、リソース、クラス、インポート状態、プロジェクト設定を調査します。
3. 有用な最小限の編集を行います。
4. 診断またはシーン検証を実行します。
5. 視覚的または動作上の根拠が重要な場合は、スクリーンショットまたはランタイムツールを使用します。

エディターのファイルシステムは、スキャンまたはインポートによって一時的にビジー状態になることがあります。アセット用ツールは、準備完了と報告されてから使用してください。

<a id="connection"></a>
## 接続

<a id="fennarastatus"></a>
### `fennara_status`

MCP サーバー、デーモン、アクティブな Godot プロジェクト、接続中のエディターセッション、コンポーネントバージョン、レンダリングコンテキスト、公開されているツール、エディターファイルシステムの準備状態を報告します。

正常時の動作:

- 1 つのプレーンテキスト状態ブロックを返します。
- 準備済みのエディターファイルシステムと、スキャン中またはインポート中の状態を区別します。
- アセット用ツールが現在利用可能かを報告します。
- 一致しないインストールを診断できるように、バージョン差を表示します。

重要な制約と失敗:

- プロジェクト単位の準備状態を報告するもので、特定のアセットパス 1 つの準備状態ではありません。
- デーモンが切断されている、アクティブプロジェクトがない、Godot プラグインが切断されている場合、それを準備済みプロジェクトとして扱わず、直接報告します。
- Godot がファイルを再インポートしている短時間は、準備状態が変わることがあります。

<a id="inspection"></a>
## 調査

<a id="getscenetree"></a>
### `get_scene_tree`

Godot を通してシーンを読み込み、そのノード階層、ノードクラス、添付スクリプト、インスタンス化されたサブシーンを返します。返されたパスは、ほかのシーンツールで使用できます。

正常時の動作:

- 作成済みシーンを書き換えずに読み取ります。
- 編集前にノードおよびインスタンス構造を可視化します。
- すべてのリソースを展開せず、結果を階層に集中させます。

重要な制約と失敗:

- 完全な 3D アセット、メッシュ、マテリアル、スケルトン、アニメーションのレポートではありません。
- Godot が読み込めないシーンは、推測したツリーではなく失敗を返します。
- 大きなリソースの詳細は、対象を絞ったプロパティまたはスクリプトの調査で確認します。

<a id="getnodeproperties"></a>
### `get_node_properties`

選択したノードについて、クラスの既定値と異なるプロパティを表示し、埋め込みリソースの有用な要約を展開します。

正常時の動作:

- 1 回の呼び出しで最大 5 個のノードを対象にできます。
- エクスポートされた GDScript プロパティと、利用可能な C# スクリプトメタデータを読み取ります。
- 不透明な値をダンプせず、アニメーション、テーマ、タイルデータ、メッシュライブラリ、スプライトフレーム、アニメーショングラフなどのリソースを要約します。

重要な制約と失敗:

- ノードを対象とするツールであり、シーン全体のリソース一覧ではありません。
- インポートされたソースアセットは、作成済み `.tscn` ノードより少ない情報しか公開しない場合があります。生成されたインポート済みリソースそのものを調査する必要がある場合は、`run_asset_import_script` を使用してください。
- 無効なノードパスは暗黙に無視されず、報告されます。

<a id="getclassinfo"></a>
### `get_class_info`

継承、プロパティ、メソッド、シグナル、enum、定数、利用可能なドキュメントを含む、Godot クラスの実際の API 面を返します。

正常時の動作:

- ランタイム ClassDB 情報は、接続中の Godot エディターから取得します。
- 組み込みクラスは、接続中 Godot のメジャーおよびマイナーバージョンに一致する公式 Godot XML ドキュメントを使用し、明示的な `master` フォールバックを備えます。
- GDExtension およびネイティブアドオンのクラスは、公式 Godot ドキュメントがあるかのように見せず、利用可能なランタイムクラスおよびプロパティ情報を返します。

重要な制約と失敗:

- 一致する上流クラス XML が利用できない場合、またはレスポンス全体を受信できない場合、ドキュメント検索は不完全になることがあります。
- ランタイム限定の動作では、小さなエディター側スクリプトプローブが必要な場合があります。
- 存在しないクラス名は、不足として報告されます。

<a id="editing"></a>
## 編集

<a id="writeorupdatefile"></a>
### `write_or_update_file`

プロジェクト内のテキストファイルを作成、書き換え、または完全一致によって置換します。

正常時の動作:

- `write` は完全な内容からファイルを作成または置換します。
- `update` は一意に一致する正確なテキストブロックを 1 つ置換します。
- GDScript とシェーダーの編集では、Godot の診断が自動的に返されます。
- シェーダーの編集では、埋め込みマテリアルデータが古いままにならないよう、参照元シーンとリソースを Godot を通して再直列化することも試みます。
- C# の書き込みでは、プロジェクト診断ビルドを 1 回要求する前に複数ファイルの編集を組み立てられます。

重要な制約と失敗:

- 更新対象テキストが曖昧または存在しない場合、任意の一致箇所を変更せずに失敗します。
- 保護された Fennara、Git、Godot キャッシュ、プラグインマニフェスト、プロジェクト設定の各パスは、このツールでは編集できません。
- 生の `.tscn`、`.tres`、`.res` を直接手術するためのものではありません。
- C# の検証は個々の書き込み後には実行されません。関係する C# 編集が完了した後、プロジェクト診断スキャンを使用してください。
- 安全に再直列化できないシェーダー参照元は、省略または警告として報告されます。

<a id="runsceneeditscript"></a>
### `run_scene_edit_script`

作成済みの 1 つのシーンまたは Godot リソースグラフに対し、エディター時に 1 つの GDScript ワーカーを実行します。Godot のオブジェクトモデルとシリアライザーを通してシーンを調査または編集する、構造化された方法です。

正常時の動作:

- 調査モードは切り離された読み取り専用のシーングラフを読み込み、保存しません。
- 編集モードはノードの追加、削除、名前変更、親の変更、リソースの割り当て、プロパティの変更、シーンの作成、Godot の直列化を通した保存を行えます。
- 既存シーンは、ワーカーがコンテキストを変更済みとマークした場合にだけ保存されます。
- 新しいノードと PackedScene インスタンスでは、Godot が意図した構造を直列化できるよう、明示的な所有権ヘルパーを使用します。
- 実行前にスクリプト診断が行われ、保存済みシーンは後続の検証を受けます。
- Godot が要求された上書きを安全に直列化できる場合、継承シーンのルートは保持されます。
- 呼び出しごとに有効な一時ワーカーパスを返すため、失敗したワーカーを最初から作り直さずに修正できます。

重要な制約と失敗:

- 読み込まれたグラフは、Run Scene を押したときと同じではありません。SceneTree に依存するゲームプレイ API、タイマー、フレーム処理、グローバル変換は、切り離されたノードで使用すると異なる動作をするか、失敗する場合があります。
- 調査モードは Fennara のコンテキスト変更ヘルパーをブロックしますが、任意の GDScript でも、ファイルシステム、エディター、OS、リソース保存への直接的な副作用を避ける必要があります。
- `.glb` や `.gltf` などのインポート済みソースファイルは、このツールでは保存されません。インポート設定には `run_asset_import_script` を使用します。
- PackedScene 内部の所有権が不正な場合、インスタンス内容が平坦化または重複するおそれがあるため拒否されます。
- 保存によって継承ルートが平坦化される場合、Fennara は元のファイルを復元し、失敗を報告します。
- 診断またはランタイムエラーが発生すると編集は停止します。失敗結果では対象シーンを作成または更新しません。ただし、一時ワーカースクリプトは再試行用に残る場合があります。

<a id="runassetimportscript"></a>
### `run_asset_import_script`

インポート済みソースアセットとその Godot インポート設定に対し、上限付きの GDScript ワーカーを 1 つエディター時に実行します。一致する `.import` サイドカーがすでに存在するモデル、テクスチャ、音声、フォント、その他の形式に対応します。

調査モードでの正常な動作:

- インポーター、生成リソースクラス、インポートの有効性、型付きの現在オプション、生成ファイル、上流依存関係を報告します。
- 古いネスト済みキャッシュエントリーを再利用せずに、生成済みリソースを読み込みます。
- インポート済み PackedScene をライブエディターの SceneTree 内へ一時的にインスタンス化し、上限付きで調査した後、保存せずに削除できます。
- 生成されたサブリソースについて上限付きの要約を提供します。
- 調査モードでは、インポートオプションの変更を永続化しません。

編集モードでの正常な動作:

- 対応する既存インポートオプションを、ネイティブの Godot Variant 型を維持したままステージングします。
- ライブエディターが `EditorFileSystem` を通して再インポートを実行します。
- 正式なインポート設定、生成出力、エディターファイルシステム状態、新しい深いリソース読み込みが検証された後にだけ、成功を報告します。
- 検証に失敗した場合、以前の設定を復元して再インポートすることを試み、その復旧が成功したかを報告します。

重要な制約と失敗:

- ソースファイルはすでにインポート済みで、有効な `.import` サイドカーを持つ必要があります。
- バージョン 1 の編集は、対応する組み込みテクスチャおよびシーンインポーターで安全な生成キャッシュ変更として分類されたオプションだけを扱います。
- インポーター識別情報、インポートスクリプト、`_subresources`、外部抽出パス、効果が不明なオプションは調査専用のままです。
- 未知のオプション、非対応オプション、誤った Variant 型の値は、変換されずに失敗します。
- `.import` ファイルの直接変更は検出され、復元され、失敗として報告されます。サイドカーの永続化は Fennara が所有します。
- ルートスクリプトを設定したインポート済みシーンは、調査ヘルパーによって一時的にインスタンス化されません。
- 依存関係は、選択したアセットのインポートに必要なファイルを表します。モデルを使用するシーン、テクスチャを使用するマテリアル、音声を再生するスクリプト、フォントを使用するテーマなど、下流のプロジェクト利用元を特定するものではありません。
- スクリプト診断、ランタイムエラー、再インポートエラー、生成ファイルの不足、無効なファイルシステム状態、再読み込み失敗がある場合、結果は成功になりません。
- ツール出力を保護するため、大きな配列とリソース内部は上限付きまたは要約されます。上限付きの結果は、すべての頂点、キー、依存関係がインラインで表示されたという保証ではありません。

<a id="projectsettings"></a>
### `project_settings`

構造化された Godot プロジェクト設定、autoload、アプリケーションメタデータ、レンダリングおよび表示設定、入力アクションを読み取り、変更します。

正常時の動作:

- 生の `project.godot` テキスト置換ではなく、Godot を認識した構造化操作を使用します。
- デッドゾーン、イベント数、読みやすいイベント要約とともに入力アクションを一覧表示します。
- コントロールを追加または更新するとき、構造化された入力イベントに対応します。

重要な制約と失敗:

- 未知の操作または無効な設定値は報告されます。
- このツールはシーンまたはスクリプト編集を置き換えません。
- スタートアップ、レンダリング、入力、アドオンの動作へ影響する変更は、引き続き検証する必要があります。

<a id="checks"></a>
## チェック

<a id="scriptdiagnostics"></a>
### `script_diagnostics`

スクリプトとシェーダーに対し、Godot を認識した診断を実行します。

正常時の動作:

- 対象を絞った GDScript およびシェーダーの呼び出しでは、最大 5 ファイルを扱えます。
- GDScript の診断は Godot の言語サーバーから取得します。
- シェーダーの診断は Godot のシェーダーパーサーから取得します。
- 対象を絞った GDScript のチェックでは、関係するシーンもメモリ上へ読み込み、シーンへの添付によって生じるエラーをスクリプトおよびシーンと関連付けられるようにします。
- プロジェクトスキャンは GDScript とシェーダーを確認し、C# プロジェクトが存在する場合は、独立した増分 C# ビルドを 1 回実行します。
- 診断用 C# アセンブリは、エディターの通常のランタイムアセンブリと分離して保持されます。

重要な制約と失敗:

- 対象を絞った C# ファイル診断はサポートされません。C# にはプロジェクトスキャンを使用します。
- プロジェクト全体のスキャンではシーンごとのインスタンス化を省略するため、特定シーンを通してスクリプトを読み込んだ場合にだけ現れる問題を見逃すことがあります。
- 言語サーバー、パーサー、ビルドの失敗は診断失敗として返され、問題なしとは扱われません。
- 診断で証明されるのは、確認したコードをテスト対象コンテキストで解析またはコンパイルできることです。ゲームプレイの正しさは証明しません。

<a id="validatescene"></a>
### `validate_scene`

1 つ以上のシーンに構造上の問題がないかを確認し、対応する場合は短いヘッドレス起動パスを実行します。

正常時の動作:

- 最大 10 個のシーンパスを受け付けます。
- 構造チェックは、不足しているスクリプトとリソース、無効なノードパス、重複した兄弟名、循環するシーン依存関係、関係するエクスポート参照を対象にします。
- 省略可能またはランタイムで割り当てられるエクスポート参照は、無条件の失敗ではなく注意事項として報告されます。
- 構造結果が問題なしの作成済みシーンは、ログと成果物を保持する 3 秒間のヘッドレス起動パスを受けます。
- 大きなシーンで結果があふれないよう、繰り返される検出事項はグループ化されます。

重要な制約と失敗:

- インポート済みソースシーンは、作成済みプロジェクトシーンとして直接起動できないため、構造検証だけを受けます。
- Fennara は検証時間の経過後、意図的にプロセスを停止します。その停止コードだけでは、シーンの失敗として扱いません。
- 短い起動パスですべてのゲームプレイ経路、見た目、性能、アニメーション品質、ユーザー操作を検証することはできません。
- 構造エラーがある場合、そのシーンではランタイムパスを実行しません。

<a id="visual-and-runtime-feedback"></a>
## 視覚およびランタイムフィードバック

<a id="screenshotscene"></a>
### `screenshot_scene`

作成済みシーンおよび対応するインポート済み 3D アセットから、視覚的な根拠を取得します。

正常時の動作:

- すべてのシーンを独立した SubViewport 内でインスタンス化します。スクリーンショット取得で作成済みシーンを開いたり変更したりすることはありません。
- アセットに環境またはライトがない場合、自動 3D フレーミングは中立なプレビュー照明を追加できます。
- 必須入力は `scene_path` だけです。`code` と `script_path` の両方を省略すると、Fennara は自動フレーミングを使って切り離されたルートを取得します。
- GDScript は通常の Godot コードを使って、1 つのノードまたはノードの配列を選択し、対象を自由にグループ化し、シーンの一部を表示または非表示にし、切り離されたシーンを一時的に変更し、`ctx.capture(...)` で取得を要求できます。これらの一時的な変更は描画されますが、作成済みシーンへ保存されることはありません。
- `await ctx.capture(...)` は、その正確な時点のシーン状態を描画し、通常の Godot `Image` を返します。ワーカーは、選択した結果を `ctx.output(image, description)` で公開する前に、取得画像を調査、比較、サイズ変更、破棄、結合できます。
- 選択した対象が最大 8 個で、スクリプトによる 3D 取得で `view` と `camera` を省略した場合、Fennara は 17 個の決定的な視点を確認し、選択ノードの可視性、読みやすい大きさ、端からの余裕、重なりの少なさを優先する視点を選びます。有用な方向がすでに分かっている場合は明示的なビューまたはカメラを使用し、離れた対象が 1 フレーム内で小さくなりすぎる場合は複数の取得を使用してください。
- スクリーンショットワーカーが受け取るのは、`ctx.root`、`await ctx.capture(...)`、`ctx.sheet(...)`、`ctx.output(...)`、`ctx.log(...)`、`ctx.error(...)` だけです。`ctx.sheet(...)` は、呼び出し側が並べた Images を、状態選択や公開を行わず、決定的で任意にラベル付きのページへ合成します。正確な作成済みフレーミングが必要な場合、取得オプション内で `ctx.root` の下にある一時 Camera2D または Camera3D を渡せます。
- カメラパス、対象パス、ビュー矩形、最上位フレーミングパラメーターは受け付けません。選択とフレーミングはすべてワーカースクリプト内で行います。
- 公開された画像はすべて保存され、一覧表示されます。画像を扱える MCP クライアントと内蔵チャットモデルは、公開された最初の 6 出力を、呼び出し順に個別の画像コンテキストとして受け取ります。それ以降の出力も保存パスから利用でき、レシートには省略された画像数が明記されます。
- 内容の少ない取得は、画像を隠すのではなく、フレーミング指標と部分的なステータスとともに返されます。

重要な制約と失敗:

- 大きな室内、部屋、レベル、特殊なスキン付きアセットでは、自動フレーミングが芸術的に有用な視点を常に推測できるとは限りません。
- 返された画像が有効でも、内容検証によってフレーミングが疎または不確実と報告される場合があります。
- テキスト専用モデルはレシートと保存パスを受け取りますが、添付画像のピクセルを直接見ることはできません。
- 読み込み、描画、取得の所有権、ファイル保存の失敗は報告されます。
- 未知の従来型スクリーンショット引数は、移行エラーとして拒否されます。
- スクリプト解析エラー、ランタイムエラー、取得呼び出しの不足、切り離されたルート外のノード、無効な一時カメラは、取得を行わずに報告されます。

<a id="runtimesession"></a>
### `runtime_session`

デーモン管理のウィンドウ付き Godot シーンを開始、確認、停止します。

正常時の動作:

- シーンプロセスを起動する前に、スタートアップゲートを実行します。
- 開始に成功すると、セッション識別子、プロセス状態、ログパス、スタートアップ検出事項、利用可能なキャプチャ情報を返します。
- 状態確認は、セッションログ全体を破棄せず、新しいランタイム出力を返します。
- 停止は、最終的なプロセスおよびログ情報を返します。
- C# プロジェクトでは起動前に、Godot の通常の Debug 出力へ実際のランタイムビルドを行い、プロセスが現在のアセンブリを使用できるようにします。
- ランタイムログが、Godot 出力、ランタイムエラー、ヘルパーマーカー、キャプチャ、停止イベントについての信頼できる唯一の情報源です。

重要な制約と失敗:

- グローバルで同時に有効にできるデーモン管理ランタイムセッションは 1 つだけです。
- スタートアップゲートに失敗すると、シーンは開きません。
- C# ランタイムビルドによって、開いているエディターの通常のアセンブリ再読み込みが発生する場合があります。
- スタートアップ準備完了マーカーは、最初のレスポンス後に到着し、後続の状態呼び出しに現れる場合があります。
- 管理対象セッションは独立した Godot プロセスであり、エディター内で手動実行されているシーンではありません。

<a id="runtimescript"></a>
### `runtime_script`

有効な管理対象ランタイムセッション内で、上限付きの GDScript プローブまたは入力ドライバーを実行します。

正常時の動作:

- ライブノードの調査、検出事項のログ、状態の待機、マッピング済みまたは低レベル入力の送信、レイキャスト、基本 UI の操作、フレームの取得を行えます。
- `ctx.frame()` で未保存の viewport Images を収集し、`ctx.sheet()` でスクリーンショットワーカーと同じ呼び出し側制御のシートを合成し、`ctx.output()` で派生 Images をゲーム内に表示せず直接公開できます。
- スクリプトが終了した後も、別のプローブ用に管理対象シーンを開いたままにできます。
- 利用可能な場合、結果には診断、ランタイム検出事項、キャプチャパス、ログパス、セッション状態が含まれます。

重要な制約と失敗:

- 有効な `runtime_session` 識別子が必要です。
- ランタイムスクリプトはエディターの `@tool` スクリプトではなく、シーン編集ワーカーとして使用できません。
- 無効な診断、タイムアウト、ランタイムエラー、終了済みセッション、利用できないノードは報告されます。
- プローブは上限付きに保つ必要があります。恒久的なゲームプレイ自動化フレームワークを置き換えるものではありません。

<a id="scrapeeditor"></a>
### `scrape_editor`

ユーザーが Godot エディターから手動でシーンを実行した後、簡潔なデバッガースナップショットを読み取ります。

正常時の動作:

- 繰り返されるデバッガー問題をグループ化し、騒がしい詳細に上限を設けます。
- 管理対象ランタイムセッションが所有しない、エディター実行時の出力調査に役立ちます。

重要な制約と失敗:

- すべてのエディター UI 要素またはログ行を読むより、意図的に狭い範囲を扱います。
- `runtime_session` から起動したシーンには使用しないでください。管理対象ランタイムログのほうが完全です。
- 何も手動実行していない場合、有用なデバッガー状態が存在しない場合があります。

<a id="built-in-chat-tools-and-controls"></a>
## 内蔵チャットのツールと操作

<a id="readfile"></a>
### `read_file`

Godot のパス処理を使って、プロジェクト単位のテキストファイルと対応画像を読み取ります。`res://` の正規化または画像処理が重要な場合に役立ちます。広範なソース探索には、引き続き通常のリポジトリツールを使用します。

<a id="execcommand"></a>
### `exec_command`

アクティブプロジェクトのルートを既定の作業ディレクトリとして、1 つの非対話コマンドを実行します。

正常時の動作:

- 時間および出力の上限を適用し、標準出力と標準エラーを取得します。
- アクティブプロジェクトのルート外にある作業ディレクトリを拒否します。
- 大きな出力をモデル会話内に残す必要がないよう、生のレシートをデーモン側に保存します。

重要な制約と失敗:

- これはプロジェクトルート制限と承認処理であり、OS サンドボックスではありません。
- 対話ターミナル、PTY、バックグラウンドセッション、標準入力ストリーム、任意の環境設定は提供しません。
- 0 以外の終了、タイムアウト、出力の切り捨ては報告されます。

<a id="chat-controls"></a>
### チャット操作

内蔵チャットは、プロジェクトを変更するツール呼び出しとランタイムツール呼び出しに対する承認モードをサポートします。読み取り専用の調査は直ちに実行できますが、変更または実行には明示的な承認を要求できます。フルアクセスではこれらのプロンプトがなくなりますが、厳格な安全確認を回避することはありません。

Godot のスクリプトエディターで選択したコードは、**Add to Chat** で添付できます。送信前に、入力欄へ添付内容が表示されます。`/provider` はプロバイダー設定を、`/model` はモデル選択を開きます。これらはチャットコマンドであり、MCP ツールではありません。

<a id="what-fennara-does-not-replace"></a>
## Fennara が置き換えないもの

次の作業には、通常の開発ツールを使用してください。

- リポジトリ全体の検索と探索
- 通常のテキストファイル読み取り
- 差分とバージョン管理
- Godot のフィードバックを必要としない編集
- 一般的なシェル作業

答えが Godot による理解、インポート、直列化、描画、検証、プロジェクト実行に依存する場合は、Fennara を使用してください。
